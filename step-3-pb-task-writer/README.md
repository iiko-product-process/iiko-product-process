# Шаг 3 — «Описание пользовательской истории (PB Story)»

Папка шага 3 продуктового процесса iiko: скилл-интервьюер, который превращает вход от продукт-оунера в оформленные задачи Epic/Story в Jira (проект `PB`) по единому шаблону.

Эпик шага в Jira: [PB-7861](https://jira.iiko.ru/browse/PB-7861) «Шаг 3: описание пользовательской истории (PB Story)» (исполнитель — Полина Алексеевцева, статус Open).

## Что можно сделать

- **Описать задачу** — скилл `pb-task-writer`: опрос продукт-оунера по блокам шаблона (по одному вопросу, с вариантами и «пропустить»), согласование структуры, затем создание задач.
- **Создать Epic/Story в Jira** — с системными полями: Component и Labels, `Epic Name` у эпика, `Epic Link` у стори, Priority (1 = Must, 2 = Should).
- **Прогнать ТРИЗ-блок** — для эпика автоматически формируется противоречие → ИКР → приёмы → ресурсы.
- **Посмотреть примеры формата** — `examples/`: шаблон эпика, шаблон стори и схема процесса от команды Law2 (пример для всех команд, не эталон).
- **Установить скилл команде** — `skill/SKILL.md` → в скиллы Hermes (см. «Установка»).

## Что должно получиться в итоге

**Единый язык описания задач и единый набор артефактов на выходе шага:** Epic/Story по шаблону — сценарии, требования, критерии приёмки, AS-IS → TO-BE для сложных процессов, зависимости и источники. Следующий участник (дизайн/разработка) начинает работу без восстановления контекста из чатов и встреч.

Что меняем: сейчас нет единого шаблона Epic/User Story, истории различаются по объёму и наполнению, в сложных процессах нет схем AS-IS/TO-BE, не хватает источников и бизнес-контекста, финальная проверка на полноту не стандартизирована.

**Что не входит** (out-of-scope эпика): продуктовые решения принимает команда — ИИ их не принимает; юридическую корректность регуляторных требований проверяет специалист; внедрение ИИ-инструмента на уровне инфраструктуры фиксируется как решение команды.

## Как устроен скилл

Скилл делает из ИИ **стандартизированного интервьюера и оформителя задач**. Он не принимает продуктовых решений: опрашивает, структурирует, подсвечивает пропуски и генерирует черновики.

**Порядок работы (7 шагов):**

1. **Вход** — продакт приносит всё, что есть: ссылки на Jira/Confluence, макеты Figma (сам факт наличия), кликабельные прототипы, текст, файлы. Недостающее не выдумывается.
2. **Разбор** — вход раскладывается по блокам шаблона с пометками: ✅ заполнено, ⬜ пусто, ⚡ противоречие, 🔍 нужно уточнить.
3. **Тип и системные поля** — эпик или стори; для стори — функциональная или ресёч; привязка к существующей задаче; Component и Labels (спрашиваются каждый раз, с вариантом «пропустить»).
4. **Опрос по пустым блокам** — по одному вопросу за раз (через `clarify`), с прогрессом `🔵 ~N%`, с 2–3 вариантами ответа и опцией «Пропустить». Свободные ответы сокращаются до сути.
5. **Согласование структуры** — до создания задач показывается план (эпик + стори внутри) и ожидается «да». Каждая стори — одна законченная ценность ≈ один спринт.
6. **Создание в Jira** — через Atlassian MCP, проект `PB`. Epic: `customfield_11443` (Epic Name) обязателен. Story: `customfield_11441` (Epic Link) — единственная связь с родителем. Priority: 1 = Must have, 2 = Should have. Assignee не ставится.
7. **Отчёт** — что заполнено, что пропущено, открытые вопросы, разногласия, что помечено «нужно уточнить», ссылки на созданные задачи.

**Дополнительно:** HTML-прототип генерируется только по запросу (один самодостаточный `.html` в стиле iikoWeb).

## Установка

Файл скилла — `skill/SKILL.md`. Чтобы Hermes его подхватил, положи его папкой `pb-task-writer` в скиллы категории `productivity`:

- Linux/macOS: `~/.hermes/skills/productivity/pb-task-writer/SKILL.md`
- Windows: `C:\Users\<логин>\AppData\Local\hermes\skills\productivity\pb-task-writer\SKILL.md`

В рабочем контейнере скилл установлен в `/opt/data/skills/productivity/pb-task-writer/SKILL.md`.

## Связь с другими шагами

- **Вход из шага 2:** гипотезы, отмеченные в прототипе кнопкой «Создать задачи в Jira через Hermes», приходят пакетом (формулировка, метрика, оценка, цель с α) — их оформление в Epic/Story делает этот скилл.
- **Выход в дизайн/разработку:** Epic + Story по шаблону со сценариями, критериями приёмки и зависимостями — без восстановления контекста из чатов.

## Что ещё не сделано (по плану эпика)
