# Скрипты шага 4

Автообновление дизайн-системы и гайда. Отдельного скилла для этого нет — работают cron-задачи.

| Скрипт | Где | Когда | Что делает |
|---|---|---|---|
| `sync-design-repos.sh` | аккаунт администратора | суббота, 10:00 | тянет `iiko-DS/Design-System` и `iiko-DS/Prototype-Guide`, заменяет копии в `04-design/` целиком, коммитит и пушит `main`, переустанавливает скиллы |
| `update-design-step.sh` | машина сотрудника | воскресенье, 09:00 | `git pull` клона процесса, переустановка скиллов; в понедельник — свежая ДС |
| `setup-design-cron.sh` | машина сотрудника | один раз | ставит обёртку для Hermes-cron и печатает параметры задачи (`0 6 * * 0`, без агента) |
| `check-setup.sh` | машина сотрудника | по требованию | чек-лист настройки: клон, токен, скиллы, вики, обновление шага 4, MCP |

Оба молчат, когда изменений нет: пустой вывод = нет уведомления.

## Настройка у администратора

```bash
bash scripts/sync-design-repos.sh --dry-run     # проверить, что изменится
```

Cron (Hermes): расписание `0 10 * * 6`, режим без агента, скрипт `<репозиторий>/scripts/sync-design-repos.sh`.

## Настройка у сотрудника

```bash
bash scripts/update-design-step.sh --dry-run    # отстаём на N коммитов?
```

Cron (Hermes): расписание `0 9 * * 0`, режим без агента, скрипт `<репозиторий>/scripts/update-design-step.sh`.
Если клона нет, скрипт создаст его сам (`~/iiko-product-process`), взяв токен из `$HERMES_HOME/.env`.

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `sync-design: не удалось получить …` | нет доступа к приватному репозиторию дизайнеров | проверить токен в `$HERMES_HOME/.env` |
| `push не прошёл` | истёк токен в remote | обновить URL remote или токен |
| `update-design: в 04-design есть локальные правки` | кто-то правил копию руками | откатить правки: `git checkout -- 04-design` |
| `обновление невозможно` | в клоне есть локальные коммиты | разобрать вручную: `git status`, `git log` |
