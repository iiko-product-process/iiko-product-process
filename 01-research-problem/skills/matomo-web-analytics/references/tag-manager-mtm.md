# Matomo Tag Manager (MTM): что даёт и чем отличается от разметки кодом

Класс вопросов: «зачем MTM, если трекинг уже стоит кодом», «чем может помочь tag manager», «что можно
поправить без релиза фронта». Разбор сделан на iiko prod (контейнер `I5llzxeu`, Matomo 5.11) — цифры и поля проверены по API/исходникам.

## Устройство

- Контейнер → версии → теги / триггеры / переменные. Публикация версии = «релиз» конфига; **Preview/Debug**,
  откат на предыдущую версию, окружения (dev/staging/prod) — то есть конфиг живёт как код, но без релиза приложения.
- Трекер MTM подключается сниппетом `mtm.js` (+ container JS) — если сниппета нет, контейнер не работает.
- В инстансе iiko контейнер веб-сайта создаётся автоматически: `TagManager.getContainers` → версия
  «0.1.0 — Создано автоматически» с тегом «Matomo Аналитика» (pageview), триггером «Просмотр страницы» и
  переменной «Конфигурация Matomo» (url/idSite/enableLinkTracking). Это заготовка, а не работающий трекинг.

## Что умеет тег «Matomo Analytics» в MTM (состав полей проверен)

`trackingType` = **pageview | goal | event** · `idGoal` + `goalCustomRevenue` (цель прямо из браузера) ·
`eventCategory / eventAction / eventName / eventValue` · **`customUrl`** (можно передать нормализованный путь
вместо реального — лечит SPA, где всё схлопнуто в `/module/index.html`) · `documentTitle` ·
`customDimensions` + флаг **«sticky»** (проставить CD на все последующие запросы) · настройки трекера
(link tracking, Do Not Track и т.п.).

**Поля User ID в теге НЕТ.** `setUserId` через MTM делается только Custom HTML-тегом с
`_paq.push(['setUserId', {{переменная}}])` (переменная читает id из cookie/localStorage/JS-переменной),
причём вызвать это надо **до первого `trackPageView`** на загрузке приложения.

## MTM vs разметка кодом

| | код | MTM |
|---|---|---|
| Кто меняет | фронт-разработчик + релиз | аналитик/админ Matomo |
| Скорость | дни–недели (спринт) | минуты (публикация версии) |
| Откат | откат релиза | переключение версии |
| Риск | регрессии продукта | изолированные правила + preview |
| Умеет лучше | серверные события, WebView/нативные приложения, e-commerce | клики/скроллы/видимость элемента/таймеры, сторонние теги, включение-выключение без релиза |
| Умеет хуже | скорость изменений | не работает в WebView/нативе; лишний JS; риск двойного трекинга; нужен владелец контейнера |

Правило ответа: MTM не «другая отправка данных» — те же `matomo.php`-запросы; выигрыш ровно один —
**правки трекинга перестают зависеть от релизного цикла фронта**. MTM выигрывает, если менять трекинг надо
чаще, чем выходят релизы, и это должен делать аналитик. Если трафик преимущественно в приложении/WebView,
нужны серверные события или релизы быстрые — MTM не нужен.

## Что закрывает MTM на iiko-кейсе (аргумент для команды)

1. `uid` без релиза: один Custom HTML-тег с `setUserId` из хранилища токена → закрывает десятки процентов
   сессий без uid (до фикса 01.10.2026 — 66%).
2. Подроуты SPA: триггер History Change + тег pageview с `customUrl`/`documentTitle` → постраничные отчёты
   оживают, пока роутинг не поправлен в коде.
3. События и цели без релиза (клик/видимость/таймер) — пока команда не задеплоит бизнес-события.
4. Отсечение тестового/dev-трафика блокирующим триггером по hostname (`localhost`, `*.test`, `*.iwr.lan`, `*-demo*`).

## Ловушки внедрения

- **Двойной трекинг**: если трекер уже подключён кодом (на iiko фронте `mtm.js` не найден — трекинг кодом),
  при включении MTM нужно решить «кто владелец»: либо MTM ставит трекер (сниппет из кода убрать), либо MTM
  добавляет только дополнительные теги. Иначе два pageview на загрузку.
- **CSP**: `analytics.iiko.services` должен быть разрешён в `script-src`/`connect-src`, иначе теги молча падают.
- **Схема событий**: у клиента уже есть свой слой (`Session`/`bounce_*`) — новые MTM-события добавляют второго
  владельца схемы; договориться о едином реестре имён/категорий.
- **Preview не оставлять публичным** (debug-режим сможет открыть кто угодно).
- Disclaimer: MTM-контейнер, версии и теги читаются Reporting API (`TagManager.getContainers`), но
  поле `User ID` в теге Matomo появится только если его добавит сопровождающий плагина — не обещать.
