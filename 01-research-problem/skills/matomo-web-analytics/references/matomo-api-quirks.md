# Matomo-инстанс iiko: API-квирки (проверено на практике)

Инстанс: `https://analytics.iiko.services/` → `index.php`, site_id=1 («iiko prod»).
Токен `MATOMO_TOKEN_AUTH` в `$HERMES_HOME/.env` — **только POST-параметром формы** (`urllib.parse.urlencode` в body); query/Bearer/JSON-body → «Authentication required».

## Уникальные метрики: доступны не везде
- **`nb_uniq_visitors`** — есть в ДНЕВНЫХ отчётах `Actions.getPageUrls` / `Actions.getPageTitles` / `VisitsSummary` / `VisitTime`.
- В **недельных** (`period=week`) отчётах `Actions.*` строки `nb_uniq_visitors` / `nb_uniq_pageviews` **отсутствуют** (ключей нет вовсе).
- **`nb_uniq_pageviews`** в этом инстансе НЕ отдаётся ни по дням, ни по неделям ни для PageUrls, ни для PageTitles.
- «Уникальные просмотры» в UI = Σ `nb_visits` по строкам (~1,85 заголовка/визит).
- Недельный уник по странице/модулю — только через **сегмент** (запросом, не полем).

## Сегменты (правила операторов)
- **`pageUrl==<полный url>`** — точное совпадение; строки flat-отчёта `Actions.getPageUrls` содержат готовое поле `segment` (закодированный полный url) — переиспользуй его.
- **`pageUrl=@<путь>`** — «содержит» (кросс-доменная агрегация). Пример `pageUrl=@/navigator` собирает navigator всех ресторанов.
- **`pageUrl@<путь>`** (без `=`) — НЕВАЛИДНО, инстанс отвечает ошибкой.
- Простой `pageUrl==/navigator/index.html` (путь без хоста) → 0 совпадений: в URL есть домен-префикс.

## Раздел (модуль) vs страница (ресторан×модуль) — главная ловушка
- `Actions.getPageUrls` **без** `flat=1` → иерархические строки верхнего уровня = **первый сегмент пути** (`navigator`, `purchase`, `till-shifts`…), агрегированы **по ВСЕМ ресторанам** (~30–60 строк). Это «по разделам/заголовкам».
- `Actions.getPageUrls` **с** `flat=1` → **те же строки уровня пути в плоском виде**: `label` = `/navigator/index.html`, плюс поля `url` (полный URL) и `segment`. **Замер 2026-09-21: разбивки по поддоменам НЕТ** — за 16.09 и flat, и non-flat дали по 185 строк и одинаковые Σ (75 092 визита / 208 870 хитов); за неделю flat даёт 106–109 строк. Прежнее описание «хост = поддомен ресторана, ~200 строк ресторан×модуль» **неверно** (200 — это столько путей с трафиком). `filter_limit=-1` — чтобы получить все строки.
- `path = url.split('?')[0].removesuffix('/index.html')` — путь из `url` извлекать можно; `host_short` из `url` — нельзя (см. раздел «Хосты/домены»).
- `showColumns=label,nb_visits,nb_uniq_visitors` сжимает payload.

## Устройства
- `DevicesDetection.getType` (period=day/week) + `segment` → топ типов (`Desktop/Smartphone/Tablet/Phablet`) с `nb_visits`; доли = `visits/сумма`.
- На каждый модуль/страницу — отдельный сегментный запрос; закладывай лимит (напр. топ-30/60), иначе долгий прогон.

## События (Events) — аудит «приходят ли»
- Плагин `Events` — core (`Plugins[] = Events` в global.ini.php): включать нечего, отчёт появляется в UI сам (Reports → Behaviour → Events, `General_Actions.Events_Events` в `API.getReportPagesMetadata`).
- Аудит-скрипт: `$HERMES_HOME/matomo_weekly/check_events.py [дней] [подстрока]` — категории/действия/имена за период, доля `nb_events_with_value`, поиск по `segment=eventCategory=@…`.
- `Events.getCategory/getAction/getName` (period=range → плоский список; `flat`/`secondaryDimension` для pivot). Через сегмент `eventCategory=@X` — поиск конкретной категории.
- Проверка «события реально из фронта»: `Live.getLastVisitsDetails` (period=day) — в `actionDetails[].type=="event"` видны `eventCategory/eventAction/eventName/eventValue`.
- Состояние инстанса: до 17.09.2026 единственная категория — `Session` (`bounce_pagehide`, `bounce_visibilitychange`, без имён и значений). С **17.09.2026** появились бизнес-события `Employees Schedule` (`open`, `shift_add_*`, `shift_update_*`, `save`, `save_added_shifts`, `excel_export`, `view_mode_change`), с **23.09** — `Marketplace` (`application_open/connect/activate/confirm`, `filter_open`, `category_select`); у бизнес-событий uid есть в 100%, у старых `Session`/`bounce_*` — почти нигде. Премиум-плагинов нет: `CustomReports.*`/`Funnels.*` → 404, `Diagnostics.*` → «API module Diagnostics not found» (значит, по ним нельзя проверить конфиг инстанса).
- Причуды, влияющие на отображение: имя события, если не задано → строка «Event Name not defined» (drill-down по именам пустой); value ДОЛЖЕН быть числом; `datatable_archiving_maximum_rows_events = 500` (по умолчанию) — при высококардинальных action/name недельные агрегаты режутся; фильтр инстанса `[Tracker] exclude_requests` (напр. `e_c==…`) может молча выкидывать события — по API не читается.
- Тест-стенды: домены `.test` в prod-инстансе отсутствуют (за 90 дней — 0 строк), т.е. по визиту с `*.iikoweb.test` нельзя судить о prod-данных — это другой инстанс Matomo.

## Хосты/домены: где искать, чтобы отличить тест-стенды от прода
- **ГЛАВНАЯ ЛОВУШКА**: в `Actions.getPageUrls` (в т.ч. `flat=1`) `label` — это ПУТЬ (`/navigator/index.html`), без хоста. Хост присутствует только как ОДИН пример в поле строки **`url`** (полный URL) и в поле `segment` (`pageUrl==<encoded>`) — это не разбивка по хостам (см. два пункта ниже). Искать `.test`/`localhost` по `label` бессмысленно — даёт ложный «0 тестовых доменов».
- Считать по хостам из `getPageUrls` **НЕЛЬЗЯ** (исправлено 2026-09-21): поле `url` — это ОДИН примерный хост на путь, а метрики строки относятся ко всем ресторанам. Пруф: строка `/navigator/index.html` за 16.09 = `url=…/sedelice-co.iikoweb.ru/navigator/index.html`, `nb_visits=18 534`; сегмент `pageUrl=@/navigator` за тот же день = 17 317 (путь по всем поддоменам), а сегмент по этому хосту `pageUrl=@sedelice-co.iikoweb.ru` = **511** визитов. Складывать `nb_hits` по `url` → вымышленные цифры по ресторану.
- Хост-специфичные цифры — только сегментом: `VisitsSummary.get`/`Actions.*` с `segment=pageUrl=@<хост>`. Перечислить хосты через `getPageUrls` невозможно (~59 хостов в поле `url` за день = один пример на путь), поэтому списки хостов из аудит-скриптов — нижняя оценка: «хост найден» валидно, «хоста нет» недоказуемо.
- Аудит тест-трафика: `$HERMES_HOME/matomo_weekly/check_test_traffic.py [idSite] [дней_от] [дней_до]` — все хосты, похожие на тестовые/внутренние (`localhost:42xx`, `127.0.0.1`, `192.168.*`, `10.*`, `vm-*`, `*.iwr.lan`, `*-demo*`, `*test*`, `:порт`), с первой/последней датой и разбивкой по дням (видно, перестал ли источник приходить после выката).
- Аудит конкретного стенда: `$HERMES_HOME/matomo_weekly/check_stand_traffic.py <base_url> <token> <подстрока_хоста>`.
- Проверка сегментом (валидируется известным хостом): `VisitsSummary.get&segment=pageUrl=@localhost:4200`. `pageUrl=@.test` → 0, если `.test`-хостов нет вовсе.
- Сайтовые настройки фильтрации: `exclude_unknown_urls` (0/1), `excluded_ips`, `SitesManager.getSiteUrlsFromId`. Если `urls` = только домен самого Matomo и `exclude_unknown_urls=0` — серверной фильтрации по домену НЕТ, любые хосты пишутся в базу; зато это позволяет уверенно говорить «если стенд шлёт в этот инстанс — его видно».

## «Уникальные посетители» vs «Пользователи» (nb_uniq_visitors vs nb_users)
- Определения из метаданных инстанса (`API.getMetadata&apiModule=VisitsSummary&apiAction=get` → `metricsDocumentation`): `nb_uniq_visitors` = уники по ID визитёра (cookie/устройство); `nb_users` = «The number of users logged in your website… unique active users that have a User ID set (via setUserId)».
- Проверка тождества: `UserId.getUsers&period=day` → число строк == `nb_users` за тот же день (на iiko: 4 015 = 4 015 на 2026-09-09).
- Разбивка причин: сегменты `userId!=` (залогиненные) и `userId==` (анонимные) — у iiko 09.09 залогиненные 12 793 визита / 5 229 уников / 4 015 users; анонимные 23 732 / 12 270 / 0.
- **Как проверить `enable_userid_overwrites_visitorid` (default 1)**: при включённой настройке idvisitor залогиненного = `substr(sha1(userId),0,16)` (см. `core/Tracker/Visit.php::setIdVisitorForExistingVisit` + `core/Tracker/Request::getUserIdHashed`). На iiko подтверждено: доминирующий `visitorId` у аккаунтов 11101/117232/16011 == sha1(userId)[:16].
- Один аккаунт может иметь несколько visitorId (визиты, где userId не передан/пришёл позже): у 11101 — 3 за день, 14 за два дня → уники всегда ≥ users даже среди залогиненных.
- Агрегация: day/week/month дают distinct за период; `period=range` НЕ отдаёт `nb_uniq_visitors`/`nb_users` (null) — UI показывает сумму дневных (`sum_daily_nb_uniq_visitors`/`sum_daily_nb_users`), которая завышает. Визит = 30 мин неактивности (`visit_standard_length=1800`), новый визит после полуночи и при смене кампании; cookie визитёра 13 мес; при `trust_visitors_cookies=0` присланная cookie валидируется по fingerprint → смена IP/UA даёт новый visitor ID.
- Репорт по аккаунтам: `UserId.getUsers` (лимит архивации `datatable_archiving_maximum_rows_userid_users = 50000`).

## «Страницы × User ID» и метрика users в page-отчётах
- **`nb_users` нет ни в одном отчёте по страницам/действиям** (в метаданных `Actions.getPageUrls` только `nb_hits`/`nb_visits`); `secondaryDimension=userId` для Actions игнорируется. Причина архитектурная: `user_id` — измерение визита, страницы — действия. Штатная матрица «аккаунт × страница» только через премиум Custom Reports или SQL (`log_visit` × `log_link_visit_action`).
- Что доступно: сегменты `userId!=` (сессии с переданным User ID) и `userId==` (без него) на любом отчёте по страницам + `userId==<id>` для конкретного аккаунта.
- Готовый отчёт (статический HTML, без JS + JSON с данными): `$HERMES_HOME/matomo_weekly/build_pages_userid.py [Д0 Д1]` → `pages_userid_<дата>.html` (сводка по дням, таблица модулей, матрица модуль×день с долей «без User ID»). Уники за период брать из `sum_daily_nb_uniq_visitors` (в range `nb_uniq_visitors` в строках отсутствует → колонка вышла бы нулевой).
- Диагностика «сессии без uid»: `$HERMES_HOME/scripts/anon_by_browser.py` (доля без uid по дням), `mixed_visitor_probe.py`, `anon_by_host.py`. На iiko в 09.2026 доля без uid была 64–66% (сессии с сотнями действий — 386 в inventory, 202 в call-center, т.е. ломалась передача `setUserId` целыми сессиями); после выкатов 01–02.10.2026 — 4–5%, остаток — легаси-паттерн `/<module>/index.html` и публичные экраны.
- Проверка гипотезы «это из-за кривого URL/роута»: одна и та же строка отчёта содержит и сессии с uid, и без (`/navigator` 09.09: 7 484 vs 9 805) → URL ни при чём. Обрыв роута на `/module/index.html` при этом отдельная проблема: `keep_url_fragment` у сайта = 2, т.е. Matomo фрагменты НЕ срезает (`shouldRemoveURLFragmentFor()` → `empty($keep_url_fragment)`), значит подроут не кладёт сам фронт (нужен `setCustomUrl`).

## Аудит «до/после выката разметки» (iiko, выкаты 17.09 и 01–02.10.2026)
- **Включение uid на всех запросах склеивает дубли визитов** (`enable_userid_overwrites_visitorid=1`): раньше активность человека распадалась на анонимный визит + визит с uid (разные idvisitor), и новый браузерный профиль начинал новый визит. Наблюдаемый эффект: визиты −44% (40 913→22 788), уники −42%, визитов/пользователя 9,4→5,0, действий на визит 5,1→9,7, **при этом пользователи +5% и действия +5%**. Это не потеря данных; не путать с инцидентом — цифры «визиты/уники» до фикса были раздуты дублями.
- **Подроуты** (нормализованный `setCustomUrl` с шаблонами `:id`/`:orderId`/`:adapterCode`): URL-строк 190→393, легаси `/<module>/index.html` с 46% до 2% уников, на новых маршрутах uid 100% и «уники ≈ users» (1 326 vs 1 268). До этого подроуты не доезжали вовсе (фрагменты Matomo не срезает — `keep_url_fragment=2`).
- **Тестовые/dev-хосты** (`localhost:4200`, `*-demo*.iikoweb.ru`, `*.iwr.lan`) отсечены с 18.09.2026 → в отчётах 0.
- Быстрый аудит, не заходя в UI: `Events.getCategory` (+ `segment=eventCategory!=Session`), `Actions.getPageUrls` (искать шаблонные URL c `:`), `VisitsSummary.get&segment=userId==` (доля сессий без uid), `VisitTime.getVisitInformationPerServerTime` по часам (виден момент включения — обрыв в середине дня), `Actions.getPageUrls`-строки `*index.html` (легаси-доля).
- Сравнение «до/после» корректно по полным рабочим дням: скрипт `$HERMES_HOME/scripts/before_after.py` (среднее Vs «после», Δ в % + производные «действий на визит», «визитов на пользователя»).

## Связки модулей: составной сегмент по pageUrl НЕ работает (обход обязателен)
- Проверено 2026-10: `segment=pageUrl=@/call-center;pageUrl=@/delivery-map` → **0 визитов**, хотя по отдельности call-center 11 912, delivery-map 3 095. Причина: два условия по одной размерности применяются к ОДНОМУ действию, а не к разным действиям одного визита. Не тратить время на подбор синтаксиса — использовать обход.
- **Обход для «модули в одном визите»**: `Actions.getPageUrls&period=range&date=<R>&segment=pageUrl=@/<A>&flat=1&filter_limit=-1&showColumns=label,nb_visits` — отчёт возвращает ВСЕ страницы визитов, где был модуль A; строки модуля B в нём = визиты, где встречались оба. Один вызов на модуль A (~5–35 с), покрывает все пары. Базу P(B|A) брать из `VisitsSummary.get` с `segment=pageUrl=@/<A>`.
- **Два уровня связи дают разные ответы**: пользовательский (пересечение uid из `UserId.getUsers&segment=pageUrl=@/<module>`) и визитный. Пример: call-center + delivery-map — 104 общих пользователя, lift 14.3, но лишь 11.7% визитов с картой содержат колл-центр → процесс растянут по сессиям (визит рвётся на 30 мин). Для вывода «это один процесс» смотреть оба уровня.
- **Транзитные экраны искажают связки**: `/navigator` (главная/точка входа) и `/user-profile` (открывают по пути) попадают в половину пар — исключать из анализа связок или выносить в справочный блок (правка пользователя: «навигатор — главная страница, связки с ней не считать»).

## Профиль «зачем заходят»: главный модуль визита × классы пользователей
- Метод: по каждому визиту определить главный модуль (максимум действий по модулям в визите), агрегировать по классам пользователей (постоянные/редкие/автоматы), нормировать на 1000 визитов класса, индекс = редкие ÷ регулярные. Выборка 1 000 редких + 400 регулярных даёт устойчивую картину по всем разделам.
- Результат iiko 01–13.10.2026: регулярные = операционка (колл-центр 104.6/1000, закупки 140.2, кассовые смены 141.0, карта доставок 12.6 → индексы 0.03–0.23); редкие = настройка/витрина (настройки 35.3, индекс 2.4; интеграции 27.3, индекс 3.14; внешнее меню 192.3, индекс 2.89; экраны гостя 5.19; маркетплейс/схема зала/WEB-KDS — практически только у редких).
- Гипотезы вида «регулярные не ходят в настройки/интеграции» проверять индексом, а не интуицией: подтвердилась в ослабленном виде (у регулярных эти разделы десятые доли процента), но у редких они занимают заметную долю — то есть это профиль «администратора», а не «оператора».

## Локализация: заголовки страниц вместо файлов локализации
- `Live.getLastVisitsDetails` в `actionDetails` отдаёт пару `url` + `pageTitle` — реальный заголовок экрана, часто локализованный («Инвентаризация», «Внешнее меню», «Создание заказа», «Счета и проводки»). Выборка по модулям (`pageUrl=@/<module>`, 30–80 визитов на модуль, 3–4 дня) собирает 300+ страниц с заголовками за ~3–5 минут; покрытие частичное — у части экранов заголовок английский или «Page Name not defined».
- `/<module>/ru-RU/index.html` — **не локализация**, а заглушка смены языка: ставит `localStorage.iikoWeb_language` и редиректит на путь без `/ru-RU`. По стандартным путям (`/assets/i18n/ru.json`, `/i18n/ru.json`, `/assets/locale/ru.json`) локали нет; в HTML/бандлах кириллицы нет — строки внутри хешированных lazy-чанков.
- Если нужны точные названия — просить у пользователя файлы локализации из репозитория (папка `client`: пути вида `i18n/locale/l10n/translat*`) **вложением в чат**: папки с локальной машины пользователя в контейнер не попадают (типовой запрос «зайди в /Users/…/iikoWeb-develop» невыполним — это не проблема доступа к Matomo).
- Черновой словарь RU-названий: `$HERMES_HOME/scripts/ru_names.py` (`D` — модуль → RU с источником и уверенностью, `SEG` — глоссарий подпутей, `route_ru()`/`section_ru()`); скрипты выгрузок добавляют русские названия к роутам, сырой путь оставляют отдельной колонкой для сверки.

## Прочее
- `VisitTime.getVisitInformationPerServerTime` по дню: labels `'00'..'23'` (без `:00:00`), есть `nb_uniq_visitors` в час.
- `filter_limit=-1` → все строки; иначе дефолт 100/50.
- Мусор в данных: `localhost:4200`, `/` без хоста, `Page URL not defined` — из таблиц не удалять, при выводе помечать.
