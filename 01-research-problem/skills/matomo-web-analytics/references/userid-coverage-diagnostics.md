# Диагностика «уникальные посетители ≠ пользователи» и покрытия User ID

Класс задач: «почему в ЛК два числа расходятся», «наши метрики врут», «у нас нет анонимного трафика».
Итог: почти всегда причина — (1) другая метрика, (2) другой период агрегации, (3) неполная передача `uid` с фронта. Разбирать в этом порядке.

## 1. Определения (брать цитатой из инстанса)

`API.getMetadata&apiModule=VisitsSummary&apiAction=get` → `metricsDocumentation`:
- `nb_uniq_visitors`: «The number of unduplicated visitors…» — уники по **idvisitor** (cookie `_pk_id…`, 13 мес; без cookie — fingerprint запроса).
- `nb_users`: «The number of users logged in your website. It is the number of unique active users that have a User ID set (via the Tracking code function 'setUserId')» — уники по **user_id**.
- `nb_visits`: сессия; новый визит после 30 мин неактивности (`visit_standard_length = 1800`), после полуночи (`create_new_visit_after_midnight = 1`), при смене кампании.
Сверка: `UserId.getUsers&period=day` — число строк == `nb_users` за тот же день (на iiko 09.09: 4 015 = 4 015).

## 2. Период — до всякой аналитики

`period=day/week/month` → distinct за период; **`period=range` не отдаёт `nb_uniq_visitors`/`nb_users`** (null), а UI показывает сумму дневных (`sum_daily_nb_uniq_visitors` / `sum_daily_nb_users`) → завышение и «разные числа в двух блоках». В подтаблицах отчётов всегда `sum_daily_*`.

## 3. Переопределение idvisitor по userId (проверяемо)

`[Tracker] enable_userid_overwrites_visitorid = 1` (default) → при запросе с userId трекер ставит **idvisitor = `substr(sha1(userId), 0, 16)`** и переписывает его по всем таблицам лога визита (`core/Tracker/Visit.php::setIdVisitorForExistingVisit`, `updateIdVisitorAcrossLogTables`; `Request::getUserIdHashed`).

Проверка на живом инстансе: взять `Live.getLastVisitsDetails&segment=userId==<uid>` и сверить доминирующий `visitorId` с `sha1(uid)[:16]` — совпадение доказывает, что настройка включена и кросс-девайс мержится (iiko: 11101 → `0fd4844adb2cbb99`, 117232 → `1f0ee5cd49ee9c66`, 16011 → `ad2c2ea06fd48920`).

## 4. Квантификация трафика без uid

```
VisitsSummary.get&period=day&date=<день>&segment=userId==      # визиты БЕЗ User ID
VisitsSummary.get&period=day&date=<день>&segment=userId!=      # визиты С User ID
```
(`userId==` с пустым значением = user id пустой; проверяется тем, что в этом срезе nb_users = 0; суммы визитов двух срезов = общий итог.)
Проходить по 5–7 дням: ровная доля = системная дыра в разметке, скачок = деплой/регресс.

## 5. Профиль сессий без uid (доказательство «это не анонимные люди»)

`Live.getLastVisitsDetails&period=day&date=today&filter_limit=1000` → для каждого визита смотреть `userId`, `visitorId`, `actionDetails` (url → модуль, число действий), `browserName`, `deviceType`.
Признаки реальной работы, а не публичного экрана: сотни действий в рабочих модулях (на iiko: 386 действий в `inventory`, 202 и 147 в `call-center`, 122 в `internal-couriers`), ровное распределение по браузерам/ОС и по хостам (80–95% без uid у топ-хостов).
Группировка по хостам нужна, чтобы отделить «одна старая сборка на одном ресторане» (там доля была бы 100% только у него) от общей дыры в коде входа.

## 6. Питфолл: тест «смешанных visitorId» ничего не доказывает

Соблазн: найти visitorId, который встречается и с uid, и без — «значит одно устройство теряет uid на части запросов». Такой кейс **структурно невозможен**: при получении uid Matomo переписывает idvisitor визита на sha1(uid), поэтому анонимный визит сохраняет cookie-ID, а залогиненный уезжает под хеш. Не выдавать «0 смешанных» ни за доказательство, ни за опровержение — вывод делать по сессиям: если во ВСЕЙ сессии нет uid (десятки/сотни действий), значит `setUserId` не вызывался в этом сценарии входа.

## 7. Локализация на фронте (передавать пользователю)

1. DevTools → Network → фильтр `matomo.php`/`piwik.php` → payload залогиненной сессии: есть ли `uid=`.
2. Сравнить два сценария: свежий вход через форму логина vs восстановленная сессия (refresh, возврат к вкладке, сохранённый токен, PWA/WebView, deep-link).
3. Гипотезы, которые обычно подтверждаются: `setUserId` вызван только в обработчике логина; вызов идёт после первого `trackPageView` и больше не повторяется; отдельные фронты/виджеты (киоск, KDS, embedded) вообще не шлют User ID.
4. Фикс: `_paq.push(['setUserId', id])` при каждой загрузке приложения и восстановлении сессии, до первого `trackPageView`.
5. Мониторинг: доля `userId==` должна пойти к нулю; уники схлопнутся к числу аккаунтов (09.09 iiko: 17 279 → ~4 015 + мультиустройство), Users не изменится.

## 8. Как держать разговор

Пользователь может утверждать, что анонимного трафика быть не может («в SaaS нельзя зайти разлогиненным»). Не соглашаться и не спорить абстрактно: показать цифры (доля визитов без uid по дням, длинные сессии в рабочих модулях), затем явно обозначить границы доказательства (см. §6) и отдать список проверок на фронте — причина находится в payload запроса, а не в Matomo.
