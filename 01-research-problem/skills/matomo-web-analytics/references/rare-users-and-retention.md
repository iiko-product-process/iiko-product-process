# Редкие пользователи и удержание: «зачем заходят, почему уходят, где подцепить»

Класс задач: продуктовый вопрос «редкие пользователи заходят мало — понять причину, что смотрят, где обрываются
и через какие разделы их возвращать». Прогон-эталон: iiko prod, 01–13.10.2026 (13 полных дней, все аккаунты с uid).
Скрипты: `$HERMES_HOME/scripts/rare_step1_hooks.py`, `rare_step2_behavior.py`, `rare_step3_report.py`.

## Порядок работы

1. **Два определения «редкого» — не смешивать, в ответе указывать оба:**
   - по классу: визитов < 10 за период (8 248 аккаунтов = 71% базы, ≈16% трафика);
   - по активности: 1–2 дня из 13 (5 638 = 51%).
2. **Удержание по модулям (точки подцепки) — сначала, это дёшево.** Период делится на W1 / W2 (по половине).
   Для каждого модуля — отдельная матрица за неделю: `UserId.getUsers&period=range&date=<W1|W2>&segment=pageUrl=@/<модуль>`.
   30 модулей × 2 недели ≈ 60 вызовов, ~20 с суммарно (простые сегменты быстрые, в отличие от compound).
   - базовая возвращаемость = доля редких W1, активных в W2 (iiko: **42,6%**);
   - `lift = возврат(модуль) / база`; модули с lift ≥ 1,2 — «крючки», ≤ 1,05 — «тупики»;
   - считать только модули с ≥ 30 редкими пользователями (иначе шум).
3. **Поведение редких по журналу — вторым шагом.** Выборка 300–500 редких (seeded random) + 100–150 регулярных
   (8+ активных дней) для сравнения. Тянуть `Live.getLastVisitsDetails` **только по дням активности** пользователя
   (сегменты ≤ 300 id на день) — так 500 редких = ~1 500 визитов вместо десятков тысяч.
   Считать: «зачем пришёл» = модуль с максимумом действий в визите; первый/последний экран визита; набор модулей за
   визит (однозадачность); медианы действий и длительности; доля визитов с 1 действием; первые переходы.
4. **Приток новых:** пользователи, которых не было в W1, но кто появился в W2 — по модулям → «входные двери».
5. **Выводы пользователю:** «крючки» и «тупики» с цифрами lift, профиль поведения редких, 3–4 продуктовые гипотезы
   (что показать/куда вести, какой экран разобрать). В отчёте явно отделять редких от регулярных по каждой метрике.

## Ловушки

1. **Не выдавать «оба редких» за один сегмент** — класс (<10 визитов) и активность (1–2 дня) дают разные числа (71% против 51%).
2. **Сегментные запросы по модулям за неделю — быстрые (~0,5 с), но compound (`a;b`) ≈ 60 с** — для hooks использовать простые сегменты.
3. **Выборку журнала тянуть только по дням активности** (иначе payload ×20); сегменты ≤ 300 id.
4. **В выводах по удержанию обязательна база** (доля возврата всех редких): без неё «64% вернулись» выглядит как абсолютный факт, а не как lift.
5. Редкие с v<10 — не выбрасывать из сегментации (они 71% базы), но не строить на них маршруты: визитов слишком мало.
