# Анализ путей и сегментов пользователей (по user_id)

Класс задач: «как используют продукт разные пользователи» — сегменты по составу модулей, основные маршруты,
связки модулей, кто «многомодульный». Прогон-эталон: iiko prod, 01–13.10.2026, **11 631 аккаунт с uid**, 76 модулей.

> Канонический скилл по этому классу — **`matomo-user-paths`** (создан в рабочей сессии, помечен как user-owned:
> автономная кураторская правка в него запрещена). Если предстоит развивать тему — попросить
> `hermes curator adopt matomo-user-paths`, тогда правила ниже можно перенести туда.

## Порядок работы (проверен)

1. **Ростер**: `UserId.getUsers` period=range filter_limit=-1 → все uid с визитами/действиями (11 631 за 13 дней).
2. **Дни активности**: `UserId.getUsers` по каждому дню → «сколько дней из N активен» (13 вызовов, ~1 с каждый).
3. **Модули**: `Actions.getPageUrls` flat=1 filter_limit=-1 → агрегация по первому сегменту пути (76 модулей).
4. **Матрица «пользователь × модуль»**: по каждому модулю `UserId.getUsers&segment=pageUrl=@/<модуль>`
   (~5–10 с на вызов; 30 модулей ≈ 6 минут) → распределение мультимодульности, пары/связки — **дёшево, покрывает всех**.
5. **Классификация аккаунтов** (см. ниже) — обязательна до любых поведенческих выводов.
6. **Пары модулей**: общие пользователи + lift = `shared / (usersA × usersB / total)`; lift ≫ 1 = реальная связка.
7. **Маршруты**: выборка людей (по 15 на страту мультимодульности, метрики «человечные»: действий/визит ≥ 3,
   визитов/день ≤ 15), `Live.getLastVisitsDetails` по дням с
   `showColumns="userId,visitServerDate,visitLocalTime,visitDuration,actions,actionDetails"` →
   нормализация экранов (убрать `/index.html`, сохранить `:id`, схлопнуть подряд идущие повторы со счётчиком) →
   матрица переходов, 2/3-граммы, входы/выходы, примеры «дней».
8. **Отчёт**: HTML (статические блоки, без JS — телеграм-предпросмотр), KPI-карточки, таблицы; пак CSV с датой в имени.

Как просит работать пользователь (iiko): сначала **пилот** на маленьком объёме в текущей сессии («покажи пример
данных»), полный прогон — **отдельной сессией на дешёвой модели** (сбор идёт скриптами, модель почти не участвует:
`background=True` + `notify_on_complete=True`); любые присылаемые файлы — с датой периода в имени (ISO);
ограничения данных проговаривать явно (окно с 01.10, фильтр автоматов, размер выборки для маршрутов).

Скрипты прогона: `$HERMES_HOME/scripts/full_step1_collect.py`, `full_step2_analyze.py`, `full_step2b_reclass.py`,
`full_step3_paths.py`, `full_step4_report.py`. Артефакты: `$HERMES_HOME/exports/user_paths_full_2026-10-13/`
(`users_segments_v2.csv`, `module_pairs.csv`, `transitions.csv`, `chains2/3.csv`, `entries/exits.csv`, `screens.csv`, `summary.json`).

## Классификация аккаунтов (ИСПРАВЛЕННАЯ — использовать эту)

Сигналы только с абсолютными порогами по объёму (v = визитов за период):

| класс | правило |
|---|---|
| `автомат` | `(v≥20 и визитов/день≥10 и действий/визит<3)` **или** `(v≥40 и действий/визит<4)` **или** `(v≥20 и визитов/день≥10 и ср. длительность визита<30 с)` |
| `подозрительный` | `(v≥20 и визитов/день≥10)` **или** `(v≥40 и действий/визит<6)` |
| `редкий` | `v<10` — в сегменты включать, в выводы о маршрутах нет |
| `человек` | остальные |

Журнальная верификация топ-20 «автоматов» (доля повторов одной цепочки, часы покрытия суток, доля визитов
с 1 действием): **подтверждено 20 из 20**. Классы «автомат» — это мониторинг/автологин/киоски: 3,1% аккаунтов,
но **16,4% трафика** — без фильтра они формируют ложную картину маршрутов.

**Пойманная ошибка (не повторять):** сигнал «модулей ≤ 3» без порога по v пометил 3 742 малоактивных аккаунта
как «подозрительных» (в первой версии классификации — 35% аккаунтов). Симптом — резкое расхождение с проверкой
журналом: у «подозрительных» низкий объём и 1–2 модуля просто потому, что они зашли пару раз.

## Ловушки

1. **Визит ≠ рабочий день**: сессия рвётся через 30 мин простоя, в полночь и при перезагрузке SPA (у курьеров до
   161 визита на аккаунт в день у ботов; у людей 2–6 визитов/день). Межмодульные связи видны только на склейке
   «день пользователя» (uid + дата; разрыв > 4 ч = отдельный блок).
2. **uid на 100% только с 01.10.2026** — окно анализа начинать с этой даты, иначе часть сессий анонимна.
3. **Матрица по модулям дешевле журнала**: агрегаты (`UserId.getUsers` + сегмент по модулю) покрывают всех аккаунтов;
   журнал — только для маршрутов выборки.
4. **Сегмент из списка uid**: `userId==a,userId==b,…` — проверено до 300 id (4 261 символ) в одном сегменте.
5. **Compound-сегменты (`a;b`) ≈ 60 с** — массовые циклы по хостам/модулям на них не строить.
6. Заголовки страниц (`document.title`) в разделах часто не проставляются — маршруты строить на URL, не на title.
