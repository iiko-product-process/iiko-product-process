# UserCountry (страны): отчёты «с каких стран заходят в модуль X» — iiko-инстанс

Проверено 2026-09-08: ad-hoc отчёт по странам пользователей модуля `nomenclature`
(раздел iiko web), период 7 дней. Рабочая папка примера: `$HERMES_HOME/matomo_nomenclature/`
(data.json + build_countries.py + итоговый html).

## Сегментация модуля (кросс-доменно)

- Фактические URL модуля живут на поддоменах ресторанов: `https://<rest>.iikoweb.ru/nomenclature/index.html`.
- Non-flat `Actions.getPageUrls` даёт строку модуля, но её поле `segment` вида
  `pageUrl=^https://analytics.iiko.ru/nomenclature` НЕ покрывает поддомены — для
  кросс-доменной агрегации использовать contains-сегмент: `pageUrl=@/nomenclature`
  (в прямом POST — как обычный параметр `segment`, urlencode сам закодирует).
- **Сверка перед сборкой**: один день (напр. 09-07) сравнить Σ по странам с числом
  модуля в `daily_dashboard.html` (nomenclature 09-07: 1 284 уник / 1 768 виз ≈
  Σ по странам 1 285 / 1 764 — сходится в пределах шума от локальных URL и соседних
  модулей с похожим путём: nomenclature-mapping, exchange-nomenclature, localhost:4202).

## Квирки UserCountry.getCountry на этом инстансе

- Страна определяется по GeoIP (IP). Строка «Unknown», код `xx` — геолокация не
  определилась (стоит проверять прокси/внутренние адреса, а не списывать).
- `period=day`: у строк ЕСТЬ `nb_uniq_visitors` (истинные дневные уники) и `nb_users`.
- `period=week` и `period=range`: `nb_uniq_visitors` ОТСУТСТВУЕТ; вместо него
  `sum_daily_nb_uniq_visitors` (сумма дневных уников — задваивает посетителя,
  заходившего в разные дни) и `sum_daily_nb_users`.
- Проверено: `sum_daily_*` за range == сумме дневных значений → методологию прототипа
  честно подписывать «уники = Σ по дням».
- `period=range` + сегмент корректно отдаёт визиты/действия/отказы по странам.
- Иконка флага: `plugins/Morpheus/icons/dist/flags/<cc>.png`; в HTML-прототипе проще
  показывать код страны (`ru · Russia`), чем тянуть картинки.

## Проверка сегмента: MCP matomo_raw vs прямой POST

- Один вызов `matomo_raw` с `extra: {flat:1, segment:"pageUrl=@/nomenclature", ...}`
  вернул НЕОТФИЛЬТРОВАННЫЕ строки (все модули) — сегмент молча не применился.
- Тот же запрос прямым POST-скриптом (api()-паттерн из `fetch_matomo.py`) отработал верно.
- Правило: если сегментный отчёт даёт подозрительно широкие цифры или flat-выборка
  содержит чужие модули — не доверять, перепроверить прямым POST и сверить один день
  с daily-дашбордом. Для «боевых» цифр сразу писать прямой POST-скрипт.

## Прототип (ad-hoc HTML-отчёт)

- Имя файла: `<module>_countries_<ГГГГ-ММ-ДД>.html`, дата = конец периода (всегда).
- Дизайн: переиспользовать CSS `daily_dashboard.html` (тёмная тема, `:root`-переменные,
  классы `.panel/.kpi/.bar-row/.mini`); текстовые блоки статичны (Telegram-предпросмотр
  без JS), JS — только фильтр таблицы как прогрессивное улучшение.
- Состав: KPI-карточки → бары всех стран → мини-график динамики топ-страны по дням →
  таблица топ-N стран по дням → детальная таблица (визиты/доля/уникиΣдн/действия/отказы)
  → блок «Выводы».
- Оговорки в шапку: «уники = Σ по дням» (range-уников нет), текущий день неполный,
  страна — по GeoIP.
- Сборка генератором из data.json (не ручным копированием цифр) — правки пользователя
  потом живут в html, генератор можно перезапускать.
