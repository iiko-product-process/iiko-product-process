## Приложение Е. История версий скилла

Каждая версия — отдельная запись с датой, составом изменений и ссылкой на архивный текст (если он сохранён). Актуальная версия — в `SKILL.md`.

### v2.1 — 2026-10-20

Добавлен формат артефакта «Баг» для задач-багов + требование к описанию PB-задачи.

- **Новый артефакт «Баг»:** когда задача — исправить баг (фактическое поведение не совпадает с ожидаемым), а не доработка с новым сценарием, вместо PRD оформляется баг по сокращённому формату: «Цель / Шаги воспроизведения / Результат (Current + Expected)». Оформление как для PRD — статья Confluence + MD-файл, номер PB-задачи и макрос Jira.
- **Правило выбора формата** дополнено строкой «Баг» в таблице «Какой PRD писать».
- **Требование к описанию PB-задачи:** в описании PB-задачи обязательно юзер стори (в формате с переносами строк) + ссылка на опубликованную спеку в Confluence; требования, критерии приёмки и сценарии не дублируются.

### v2.0 — 2026-09-27

Переход на согласованный с разработкой стандарт **«Формат PRD»** + интервью-режим сбора требований.

- **Артефакт приведён к стандарту «Формат PRD»** (wiki.iiko.ru, IIKOWEB, pageId 181776249): полный PRD — 14 разделов (◇ — необязательные), сокращённый PRD — 5 разделов; правило выбора формата; статья Confluence + MD-файл с тем же содержанием; макрос Jira + TOC после заголовка; требования к визуальным материалам (прототип / промпт к прототипу / скриншот-макет); размер истории до недели и декомпозиция; проверка готовности.
- **Новый интервью-режим** (главное изменение): скилл сам задаёт вопросы по одному, следующий только после ответа; 14 групп вопросов в `references/questions-bank.md`; обязательные группы — «ограничения», «вопросы к разработке», «схемы»; правила фиксации ответов (ответ в требования, а не в переписку).
- **Прототип и промпт к прототипу:** порядок «требования → прототип → таблица состава экрана → перечень демонстрационных упрощений → промпт для воспроизведения → вложение в статью».
- **Схемы:** таблица «признак в задаче → тип схемы», обязательный вопрос «нужны ли схемы»; актуализированный рецепт рендера Mermaid (в новой версии mermaid-cli опция `-w` удалена → `--size` + `-s`; локальный Chromium из `/opt/hermes/.playwright/`; резервный путь — mermaid.ink с парой `width=&scale=`).
- **Новые файлы:** `references/prd-format.md` (текст стандарта), `references/questions-bank.md`, `references/pb-task-8-sections.md` (прежний формат), `templates/prd-full.md`, `templates/prd-reduced.md`.
- **Пример эталонного PRD:** статья «Пример PRD» (pageId 181776251, PB-5671, «Реквизиты юр.лица заказчика»).
- Прежний формат «задача в 8 разделов» сохранён, но применяется только если артефакт нужен именно как PB-задача.

### v1.0 — 2026-08-23 (уточнения до 2026-09-25)

Исходная версия: подготовка спецификации к разработке по 9 этапам с гейтами (бизнес-постановка → As-is → To-be → системное взаимодействие → сценарии → вводные и ограничения → спецификация → ревью → передача в разработку), правила диаграмм, чек-лист передачи, шаблон sequence diagram, адаптация под продукт производства готовой еды (подводные камни ПРК/Fabix), артефакт — «задача в 8 разделов».

- Архивный текст: `versions/SKILL-v1.0-2026-09-25.md` (в исходном файле frontmatter был помечен `version: 2.0.0`; линия версий приведена к 1.x, чтобы обновление получило номер 2.0).
- Формат «задача в 8 разделов» перенесён в `references/pb-task-8-sections.md`.
