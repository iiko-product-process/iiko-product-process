# Skills inbox — сбор наработок сотрудников без git

Схема: у сотрудника **ничего не нужно делать с git**. Его Hermes раз в неделю собирает локальные
скиллы, сравнивает с манифестом канона, пакует отличия в архив и отправляет — в папку или в Telegram.
Админ раз в неделю получает один markdown-дайджест по всем архивам.

**Когда использовать:** раскатка процесса на команду, где люди не работают с git; регулярный сбор
эволюции скиллов; «пришлите, что у вас появилось».
**Когда не использовать:** сотрудник уже работает через PR (там хватает `share-to-common`), или речь
об артефактах задач (они живут в папке задачи, а не в скиллах).

Два скрипта лежат рядом, в `scripts/`:

| Скрипт | Где запускается | Что делает |
|---|---|---|
| `collect-my-skills.sh` | у сотрудника | сравнивает `$HERMES_HOME/skills` с манифестом канона, пакует новые/изменённые в `skills-<автор>-<дата>.tar.gz`, отправляет в папку или Telegram |
| `skills-digest.sh` | у админа | распаковывает все архивы, дедуплицирует одинаковые скиллы по sha1, считает ±строк от канона, собирает `digest-<дата>.md` |

## Роли и что требуется

| Роль | Действия | Настройка |
|---|---|---|
| Сотрудник | **никаких действий с git** | один раз: cron + канал доставки |
| Админ | раз в неделю прочитать дайджест и решить судьбу каждого скилла | один раз: папка-инбокс + cron |

## Манифест канона

Манифест — это TSV `name<TAB>sha1<TAB>version` по скиллам канона. Он нужен сотруднику, чтобы скрипт
понимал, что «идентично канону» и отправлять не надо.

Админ генерирует манифест из своего клона канона:

```bash
CANON=/opt/data/iiko-product-office-skills
{
  find "$CANON" \( -path "$CANON/skills/*/SKILL.md" -o -path "$CANON/step-*/skill/SKILL.md" \
       -o -path "$CANON/step-*/skills/*/SKILL.md" -o -path "$CANON/step-*/skills/*.md" \) -type f
} | while IFS= read -r f; do
  name=$(sed -n 's/^name:[[:space:]]*//p' "$f" | head -1)
  ver=$(sed -n 's/^version:[[:space:]]*//p' "$f" | head -1)
  [ -n "$name" ] && printf '%s\t%s\t%s\n' "$name" "$(sha1sum "$f" | cut -d' ' -f1)" "${ver:-}"
done | sort > manifest.tsv
```

Файл `manifest.tsv` кладётся рядом со скриптом у сотрудника (или скачивается из общего места).
Нет манифеста — скрипт всё равно работает, но отправит все скиллы подряд, как новые.

## У сотрудника: одна настройка, дальше тишина

1. Положить скрипт и манифест:

```bash
mkdir -p ~/skill-tools
cp collect-my-skills.sh manifest.tsv ~/skill-tools/
chmod +x ~/skill-tools/collect-my-skills.sh
```

2. Проверить вручную, ничего не отправляя:

```bash
~/skill-tools/collect-my-skills.sh --manifest ~/skill-tools/manifest.tsv --author "$USER" --dry-run
```

3. Выбрать доставку и создать cron (раз в неделю, пятница 17:00).

**Вариант «папка»** (рекомендуется для команды — токенов никому не раздаём):

```bash
~/skill-tools/collect-my-skills.sh --manifest ~/skill-tools/manifest.tsv \
  --author "$USER" --out /mnt/skills-inbox
```

**Вариант «Telegram»** — на каждой машине нужен токен бота и chat_id админа; если доставка идёт
в тему группы, добавляется `TG_THREAD` (id темы):

```bash
TG_TOKEN=... TG_CHAT=... TG_THREAD=... TG_PROXY=socks5h://proxy:1080 \
~/skill-tools/collect-my-skills.sh --manifest ~/skill-tools/manifest.tsv --author "$USER" --telegram
```

Куда доставлять — тема в группе или отдельный чат:

| Сколько людей | Куда | Почему |
|---|---|---|
| 1–5 | **отдельный бот + личный чат** с ним | проще всего: нет тем, поиск по имени файла `skills-<логин>-<дата>.tar.gz` |
| 5–15 | **отдельный бот + приватная группа с темами**, по теме на человека (`TG_THREAD` = id темы) | у каждого свой поток, видно прогресс, не надо искать по чату |
| много / регулярно | папка (SMB/Nextcloud) + дайджест админу в бот | чужие архивы не ходят через Telegram |

Темы в группе создаёт человек (бот не умеет); бот должен быть участником группы. Id темы берётся из
ссылки `https://t.me/c/…/<id>` или из `getUpdates` (`message_thread_id`). Файл — до 50 МБ.
**Не используйте для этого бота, которого читает команда**: с токеном можно читать апдейты бота,
то есть чужие архивы. Отдельный бот = отдельный токен, который можно отозвать без последствий.

Постановка в cron (Гермес сотрудника делает это сам): расписание `0 17 * * 5`, режим `no_agent`,
скрипт `~/skill-tools/collect-my-skills.sh` с аргументами из выбранного варианта. Пустой вывод =
нет новинок = уведомления не будет.

## У админа: дайджест раз в неделю

```bash
skills-digest.sh --inbox /mnt/skills-inbox \
  --canon-repo /opt/data/iiko-product-office-skills \
  --out /opt/data/reports/digest-$(date +%F).md
```

Что получается в отчёте:

| Раздел | Содержимое |
|---|---|
| Шапка | сколько архивов, сколько уникальных скиллов, сколько идентичных канону пропущено |
| **Требует внимания** | скиллы, где найдены строки, похожие на секреты (токены, ключи, PEM) — читать до переноса |
| **Новые скиллы** | которых нет в каноне: имя, версия, авторы, размер, путь к распакованным файлам |
| **Изменённые** | есть в каноне, но sha1 другой: ±строк считается от версии канона |
| «Что дальше» | напоминание: в канон только после проверки на секреты и совместимость |

Дедупликация: одинаковый скилл (совпадение sha1) от трёх человек — одна строка, авторы через запятую.
Идентичные канону не показываются вообще.

Cron у админа: `30 18 * * 5`, режим `no_agent`, скрипт `skills-digest.sh`, доставка в Telegram
(у админа канал уже настроен) или файл в общую папку.

## Безопасность

- **Не раздавайте токен бота сотрудникам без нужды.** С токеном можно читать апдейты бота и писать
  от его имени. Для команды безопаснее режим «папка»: скрипты сотрудников кладут архив в общую папку,
  а в Telegram его отправляет только Hermes админа.
- Скрипт **сканирует** скиллы на токены/ключи и помечает такие как «требует внимания», но не удаляет
  файлы: решает человек.
- Не отправляются файлы больше 5 МБ; артефакты задач в архив не попадают (только каталоги скиллов).
- Манифест канона не содержит секретов — это только имена, sha1 и версии.

## Проверка, что схема работает

```bash
# 1) сотрудник: сухой прогон, ничего не отправляет
~/skill-tools/collect-my-skills.sh --manifest manifest.tsv --author test --dry-run

# 2) админ: дайджест по тестовому инбоксу
skills-digest.sh --inbox /tmp/test-inbox --canon-repo "$CANON" --out /tmp/digest-test.md
```

Ожидаемо: в dry-run видно состав архива; в дайджесте — таблица со статусами и путями к файлам.

## Типовые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| «новых и изменённых скиллов нет», хотя скилл создан | не передан `--manifest` или в нём старая версия | передать манифест, проверить `sha1sum` скилла |
| в архив попали все скиллы | манифеста нет вообще | положить `manifest.tsv` рядом со скриптом |
| дайджест пустой | архивы не распаковались или лежат в другой папке | проверить `--inbox`, посмотреть `_work/` |
| Telegram отвечает ошибкой | нет доступа к api.telegram.org без прокси | задать `TG_PROXY` (socks5h://…) |
| «Bad Request: message thread not found» | неверный `TG_THREAD` или тема удалена | взять id темы из ссылки `t.me/c/…/<id>` |
| одинаковый скилл у двух людей | это норма: дедуп по sha1, в отчёте одна строка | — |
