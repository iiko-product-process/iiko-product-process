# Сбор наработок сотрудников без git

Сотрудник не работает с git: его новые и изменённые скиллы собираются в архив и уходят в Telegram-бота.
В репозитории лежит только эта, «сотрудническая» часть. Разбор архивов и дайджест — на стороне
администратора и в репозиторий не входят.

**Когда использовать:** настроить еженедельный сбор у сотрудника, отправить наработки вручную,
объяснить, как передать скилл без git.
**Когда не использовать:** скилл нужно положить в общий слой — `share-to-common`; установить скиллы из
репозитория — `git-skills-install`.

## Что делает сотрудническая часть

| Скрипт | Где | Что делает |
|---|---|---|
| `collect-my-skills.sh` | у сотрудника | сравнивает `$HERMES_HOME/skills` с манифестом канона, пакует новые и изменённые скиллы в `skills-<автор>-<дата>.tar.gz`, отправляет в Telegram-бота или в папку |

Отправка: бот `@Cron_iiko_skill_bot`, вложения до 50 МБ. Если бот не настроен — архив просто остаётся
в `$HERMES_HOME/skill-reports`.

## Настройка: одна команда

```bash
bash ~/iiko-product-process/scripts/setup-all.sh --repo ~/iiko-product-process
```

Что появляется:

- манифест канона `$HERMES_HOME/canon-skills-manifest.tsv` — по нему скрипт понимает, что «идентично
  канону» и отправлять не надо;
- обёртка `$HERMES_HOME/scripts/skills-collect-weekly.sh`;
- cron-задача: пятница, 10:00 МСК (`0 7 * * 5`), режим без агента, пустой вывод = нечего отправлять.

Дальше сотрудник ничего не делает: новые и правленые скиллы уходят сами раз в неделю.

## Манифест канона

TSV `name<TAB>sha1<TAB>version`. Обновляется при каждом `setup-all.sh` (и вручную):

```bash
bash ~/iiko-product-process/scripts/make-skills-manifest.sh --repo ~/iiko-product-process \
  > "$HERMES_HOME/canon-skills-manifest.tsv"
```

Нет манифеста — скрипт всё равно работает, но отправит все скиллы подряд, как новые.

## Отправка в Telegram

Нужны переменные окружения (или те же значения в `.env`):

| Переменная | Что это |
|---|---|
| `TG_TOKEN` | токен бота `@Cron_iiko_skill_bot` |
| `TG_CHAT` | id чата или группы, куда приходит архив |
| `TG_THREAD` | id темы, если архив собирается в теме группы |
| `TG_PROXY` | прокси, если Telegram недоступен напрямую |
| `TG_API` | подмена адреса API — только для тестов |

Ручная отправка:

```bash
bash <репозиторий>/skills/skills-inbox/scripts/collect-my-skills.sh \
  --home "$HERMES_HOME" --manifest "$HERMES_HOME/canon-skills-manifest.tsv" --telegram
```

Без `--telegram` архив складывается в `--out` (по умолчанию `~/skill-reports`).

## Безопасность

- Скилл с признаками секрета (токен, ключ, PEM) не уходит молча: помечается «внимание» и остаётся
  в отчёте — разобрать руками.
- Файлы больше 5 МБ в архив не попадают.
- `.env`, пароли и приватные ключи не отправляются никогда.
- Токен бота и id чата — только в окружении, не в скилле и не в репозитории.

## Проверка

```bash
# что будет отправлено, без отправки
bash <репозиторий>/skills/skills-inbox/scripts/collect-my-skills.sh \
  --home "$HERMES_HOME" --manifest "$HERMES_HOME/canon-skills-manifest.tsv" --dry-run
```

Ожидаемо: «новых 0, изменённых 0, идентичных N» на чистой настройке. Появился свой скилл — «новых 1».
Обёртка `skills-collect-weekly.sh` на таком состоянии молчит.

## Типовые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| отправлено 39 скиллов, все «новые» | нет манифеста канона | `make-skills-manifest.sh` → файл рядом со скриптом |
| `Telegram ответил ошибкой` | неверный `TG_CHAT`/`TG_THREAD` или бот не в чате | проверить id и добавить бота в чат |
| архив не создаётся | нет прав на `--out` | указать другой каталог |
| пусто и код 0 | нечего отправлять | это нормально |
