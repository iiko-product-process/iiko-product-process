# Сбор наработок и инвентарь скиллов

Сотрудник не работает с git. Скрипт собирает **два сигнала** и отправляет одним архивом
в Telegram-бота или в папку. В репозитории — только эта, сотрудническая часть; разбор архивов
и дайджест остаются на стороне администратора.

| Сигнал | Что это | Что уходит |
|---|---|---|
| **Наработки** | новые и изменённые **процессные** скиллы (из канона или по шаблонам имени) | содержимое: `SKILL.md`, `scripts/`, `references/` |
| **Инвентарь** | **все** локальные скиллы | только метаданные: имя, версия, sha1, категория, в каноне/нет, дата |

Содержимое чужих скиллов (не процессных) не отправляется никогда — только строка в инвентаре.
Это отвечает на «что стоит у людей» без риска утечки.

## Как различаются процессные и чужие

1. Имя есть в манифесте канона → **процессный** (сравнивается sha1: идентичен / изменён).
2. Имени нет, но оно совпадает с шаблоном из `process-skill-patterns.txt`
   (`iiko`, `pb-`, `jira`, `pyrus`, `matomo`, `spec`, `design`, …) → **новый процессный**.
3. Всё остальное → **чужой**: только инвентарь.

Шаблоны лежат рядом со скриптом: `skills/skills-inbox/process-skill-patterns.txt`
(строки-подстроки, регистр не важен). Свой набор можно передать через `--patterns FILE`.

## Настройка: одна команда

```bash
bash <папка процесса>/scripts/setup-all.sh --repo <папка процесса>
```

Появляются:

- манифест канона `$HERMES_HOME/canon-skills-manifest.tsv` — по нему скрипт отличает «идентично
  канону» от наработок;
- обёртка `$HERMES_HOME/scripts/skills-collect-weekly.sh`;
- cron-задача: пятница, 10:00 МСК (`0 7 * * 5`), режим без агента.

Скрипт молчит, если с прошлой отправки ничего не изменилось (сравнивается отпечаток инвентаря).
Неотправленные наработки не теряются: уедут при следующем изменении состава или по `--force`.

## Ручной запуск

```bash
# что будет отправлено, без отправки
bash <папка процесса>/skills/skills-inbox/scripts/collect-my-skills.sh \
  --home "$HERMES_HOME" --manifest "$HERMES_HOME/canon-skills-manifest.tsv" --dry-run

# отправить в Telegram
... --telegram

# сложить в папку
... --out ~/skill-reports

# отправить, даже если ничего не менялось
... --telegram --force
```

## Что внутри архива

```
skills-<автор>-<дата>/
  skills/<имя>/…        только процессные наработки (новые и изменённые)
  inventory.json        все локальные скиллы, только метаданные
  manifest.json         автор, дата, хост, счётчики
  report.md             что уходит и зачем
```

`inventory.json` — единственный источник ответа на «что стоит у сотрудника»: там `in_canon`,
`canon_version`, `status` (`identical` / `changed` / `new` / `attention` / `other`).

## Telegram

| Переменная | Что это |
|---|---|
| `TG_TOKEN` | токен бота `@Cron_iiko_skill_bot` |
| `TG_CHAT` | id чата или группы |
| `TG_THREAD` | id темы, если архив идёт в тему |
| `TG_PROXY` | прокси, если Telegram недоступен напрямую |
| `TG_API` | подмена адреса API — только для тестов |

## Безопасность

- Процессный скилл с признаками секрета (токен, ключ, PEM) получает статус `attention`:
  уходит отдельно и помечается, чтобы разобрать руками.
- Чужие скиллы не отправляются содержимым вообще — только метаданные.
- Файлы больше 5 МБ в архив не попадают.
- `.env`, пароли и приватные ключи не отправляются никогда.
- Токен бота и id чата — только в окружении.

## Проверка

```bash
bash <скрипт> --home "$HERMES_HOME" --manifest "$HERMES_HOME/canon-skills-manifest.tsv" --dry-run
```

Ожидаемо на чистой настройке: «наработок 0 … идентичных 37», инвентарь — по числу локальных скиллов.
Появился свой процессный скилл — «новых 1»; чужой — только рост инвентаря.

## Типовые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| все скиллы «новые» | нет манифеста канона | `make-skills-manifest.sh` → файл рядом со скриптом |
| наработка не попала в архив | имя не из канона и не подходит под шаблоны | добавить строку в `process-skill-patterns.txt` |
| каждую неделю один и тот же архив | изменения есть, но не менялись | это норма: `--force` или ждать изменений |
| `Telegram ответил ошибкой` | неверный `TG_CHAT`/`TG_THREAD` или бот не в чате | проверить id и добавить бота в чат |
| пусто и код 0 | нечего отправлять | нормально |
