# Папка задачи: артефакты и история работ (`ARTIFACTS/` в Hermes wiki)

Каждая задача процесса живёт в **отдельной папке внутри `ARTIFACTS/`** в Hermes wiki: заметки, артефакты и вся история работ — там, в одном месте. Скилл заводит папку при старте задачи и поддерживает в ней порядок. В git-репозиторий артефакты не попадают.

## Когда применять

- старт любой новой задачи: «начинаем задачу …», «заведи задачу …»;
- пришёл артефакт по задаче (карточка проблемы, список гипотез, story, PRD, презентация, интервью, выжимка встречи);
- «положи в задачу …», «где лежит … по задаче …»;
- «покажи историю задачи», «что по задаче сделано»;
- задача переходит на следующий шаг процесса.

## Где живут задачи (TASKS_ROOT)

Корень задач ищется по порядку:
1. переменная окружения `IIKO_TASKS_ROOT`;
2. файл `~/.hermes/iiko-tasks-root` (путь сохраняется при первой настройке);
3. папка `ARTIFACTS/` — отдельная папка в дереве (не внутри `notes/`): обычно `~/.hermes/ARTIFACTS` или `~/ARTIFACTS`;
4. если ничего не найдено — **спроси пользователя**, где его Hermes wiki, создай там `ARTIFACTS/`
   (структуру возьми из этого скилла) и сохрани путь в `~/.hermes/iiko-tasks-root`.

Путь по умолчанию не прошивается: он ломается на любой другой машине.

## Один дом задачи

- **Источник правды — Hermes wiki**: `ARTIFACTS/<слаг>/`. Карточка, журнал и артефакты живут там.
- **Рабочая папка** (`~/work/<KEY>-<слаг>`) — место, где идёт работа: черновики, прототипы, выгрузки. Она временная.
- Одна задача — одна папка в вики. Второй папки «на всякий случай» не заводим.
- Работаем в рабочей папке, затем переносим в вики скриптом (ниже). Расхождение содержимого — повод синхронизировать, а не «оставить как удобнее».

## Синхронизация рабочей папки в вики

```bash
python3 skills/task-workspace/scripts/sync-task.py \
  --from ~/iiko_process/ARTIFACTS/pb-7105-nacenka-v-prikazah \
  --task "<wiki>/ARTIFACTS/pb-7105-price-orders" --dry-run     # сначала план
# без --dry-run копирует; --journal дописывает строку в журнал задачи
```

Скрипт раскладывает по правилам: `context.md` → `01-проблема/`, `spec.md` и `decisions.md` →
`05-спека/`, `confluence/` → `01-проблема/исследования/confluence/`, `prototypes/` и `references/` →
`04-дизайн/`, остальное — в `материалы/`. Совпадающие файлы пропускает, расходящиеся не
перезаписывает без `--overwrite`, карточку и журнал не трогает (кроме строки с `--journal`).

## Структура папки задачи (шаблон — `ARTIFACTS/_шаблон/`)

```
<слаг>/
  README.md        карточка задачи: статус, текущий шаг, кто ведёт, ссылки
  журнал.md        история работ: дата · что сделали · артефакты · кто
  01-проблема/     02-гипотезы/     03-требования/   04-дизайн/
  05-спека/        06-реализация/   07-пилот/
  материалы/       встречи/
```

Что куда класть:

| Что | Куда |
|---|---|
| Сигнал, карточка проблемы, результаты валидации | `01-проблема/` |
| Списки гипотез (снапшоты), решения по приоритизации, ICE | `02-гипотезы/` |
| Story / продуктовые требования, брифы для дизайна | `03-требования/` |
| Макеты, прототипы, дизайн-ревью | `04-дизайн/` |
| PRD / спецификация | `05-спека/` |
| Сопровождение, приёмка | `06-реализация/` |
| Пилот, запуск, метрики пилота | `07-пилот/` |
| Входные файлы: презентации, документы, выгрузки | `материалы/` |
| Исследования: интервью, данные, конкуренты, бенчмарки | `01-проблема/исследования/` |
| Заметки и выжимки встреч по задаче | `встречи/` |
| Карточка задачи и история | `README.md`, `журнал.md` |

## Порядок работы

### A. Завести задачу

1. Собери минимум: название, слаг (латиницей, короткий, без дат), кто ведёт, источник сигнала, ссылки. Чего нет — пометь «уточнить», не выдумывай.
2. `cd <TASKS_ROOT> && cp -r _шаблон <слаг>`.
3. Заполни `README.md` (карточка) и первую строку `журнал.md`.
4. Запись в журнал: `Задача: новая задача «<название>» (<слаг>)`.

### B. Положить артефакт

1. Определи задачу и шаг, к которому относится артефакт.
2. Выбери папку по таблице «что куда».
3. Положи файл: имена понятные (русские, через дефис; входящие файлы — под исходными именами). Существующие файлы не перезаписывай — при конфликте имён добавь суффикс версии/даты.
4. Добавь строку в `журнал.md` (дата · что · файл · кто).
5. Сохранить в вики. В ответе — коротко: путь и что это.

### C. Показать историю

1. Прочитай `журнал.md` и список файлов папки задачи.
2. Ответь коротко: статус, текущий шаг, последние записи, ключевые файлы путями. Не пересказывай всё содержимое.

### D. Сменить статус / шаг

Обнови `README.md` (статус, текущий шаг, артефакты по шагам) и добавь запись в журнал.

## Журнал (формат)

| Дата | Что сделали | Артефакты | Кто |
|---|---|---|---|
| 2026-10-01 | Пример: разобрана презентация, собрана карточка проблемы | `01-проблема/карточка-проблемы.md` | Hermes |

Записи добавляются вниз, старые не удаляются. Каждое действие по задаче — строка.

## Правила

- Слаг папки — латиницей; название задачи — внутри README.
- Живые данные сервисов (список гипотез в прототипе шага 2, сервис на 8330) остаются в своих местах — в папке задачи снапшоты, решения и ссылки на источник.
- Ничего не удаляем без явного согласия; ничего не перезаписываем молча.
- Секреты и персональные данные — не кладём; файлы >10 МБ — с подтверждения.
- Каждое действие — строка в журнале. Отдельный git для папки задачи не нужен: вики синхронизируется своим механизмом.

## Установка (для команды)

Канон скилла — этот файл в репозитории. В `$HERMES_HOME/skills` он ставится установщиком
(`install-skills-from-repo.sh`); ручные правки в установленной копии при обновлении не затираются,
но и в канон не попадают — правку предлагают администратору.

1. Папка процесса подключена в Hermes и скиллы установлены — подключение описано в `process-setup` и `git-skills-install`.
2. В Hermes скилл подключается из клона (симлинк на каталог скилла) или читается по пути из
   клона; копия файла — нет.
3. `version` в frontmatter поднимается при каждой правке, изменения — предложением администратору.
