# Длинные расшифровки: параллельные сабагенты + сверка результата

Когда приходит несколько расшифровок по 40–50 мин (40–50 тыс. знаков каждая), читать их в основной контекст
расточительно: делегируй по одной встрече на сабагента (`delegate_task` с `tasks=[…]` — запускаются параллельно),
а сам проверяй и сохраняй. Проверено на четырёх «Дейли дизайнеров» (14.09–17.09.2026).

## Подготовка (в родителе, до делегирования)

1. Извлечь текст каждого `.docx` в `/tmp/<tag>.md` (см. `notes-vault-delivery.md`) и **вычистить control-символы**
   (`re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f]', ' ', t)`) — иначе чтение спотыкается.
2. Скопировать оригиналы в `raw/<ГГГГ-ММ-ДД>_<slug>.docx` (это локальная, gitignored папка — можно делать до выжимки).
3. Убедиться, какие встречи уже есть в vault, чтобы сабагент не породил дубль (фрагмент vs полная запись).

## Контракт для сабагента (в `context`, дословно)

- Путь к файлу + **как его читать**: «`read_file` может ответить „Binary file“ на плотном русском тексте — тогда
  не бейся, выведи куски через `terminal` python-ом: `python3 -c "t=open('/tmp/d3.md',encoding='utf-8').read(); print(t[:20000])"`,
  затем `t[20000:45000]`. Прочитай ВЕСЬ текст».
- Заголовок встречи: дата, время, длительность — чтобы он не изобретал шапку.
- Роль встречи и кто что делает (строка контекста: «еженедельный дейли команды дизайна, руководитель — Павел»),
  плюс список типовых терминов, которые ASR курочит.
- **Точный формат вывода**: frontmatter (title/date/kind/tags/source) → шапка (дата, длительность, участники, формат)
  → 4–7 тематических блоков с таймкодами → `## Договорённости и следующие шаги` (`- [ ] Ответственный: … · Суть: …`)
  → `## Связи` с вики-ссылками, которые ты передаёшь ему verbatim.
- «Верни ТОЛЬКО markdown, без пояснений» и «**не создавай файлы**» — сабагенту запрещено писать вне `$HERMES_HOME`
  (`HERMES_WRITE_SAFE_ROOT`), попытка записи в `/tmp` помечается как failed file-mutation в его отчёте. Файл создаёт родитель.
- «Не выдумывай: неразборчивое — `[?]` или как в тексте. Лучше меньше, чем красивая выдумка».

## Сверка выжимки перед сохранением (обязательный шаг)

Выжимка сабагента — **самоотчёт, а не факт**. Перед записью в vault грепни исходник по конкретике из его текста
(это 1 команда python с циклом по ключевым словам, дешевле, чем перечитывать):

```python
import re
t = open('/tmp/d3.md', encoding='utf-8').read()
for pat in ['пагинатор','сборщик','лояльност','Ксюш','шапк','Максим','планшет','явк']:
    ms = [m.start() for m in re.finditer(pat, t, re.I)]
    print(pat, len(ms))
    for s in ms[:3]: print('   ', t[max(0,s-120):s+120].replace('\n',' | '))
```

Проверяй: имена спикеров и их «первую реплику в 11:13», числа (3–4 часа, 33%, 46 мин), названия задач,
сроки. Что нашлось — оставляй; чего нет — вырезай или помечай `[?]`.
Реальные правки после такой сверки: «ЕГИС/ЭГОИС» → **ЕГАИС** (в тексте «э г а и с», «егэса», «эгоизд»);
«комбо (первое и второе)» — достройки в источнике не было, убрано.

## Мелочи, которые экономят время

- Правь выжимки сабагента сам (заголовки, теги, ссылки) и пиши финальный файл `write_file` — не переспрашивай сабагента.
- Теги пиши по-русски и добавляй `транскрибация` — так они согласованы с остальным vault.
- Если сабагент перепутал порядок/участников — сверься с шапкой файла, а не с его шапкой заметки.
