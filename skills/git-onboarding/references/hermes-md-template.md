# Правила для Гермеса в репозитории без своего `.hermes.md`

Шаблон нужен только для репозитория, где правил ещё нет. В `iiko-product-process` файл
`.hermes.md` уже лежит в корне: его правят через PR, свой второй не заводят.

Кладётся в **корень клона**, Hermes читает его автоматически; приоритет выше `AGENTS.md`,
действует на все подпапки до корня git. Личный файл не коммитить:
`printf '.hermes.md\n' >> .git/info/exclude`.

# Правила работы с <название репозитория>

- Канон: https://github.com/<орг>/<репо> (роль read). Мой форк — `origin`, канон — `upstream`.
- Перед ответом по процессу проверить репозиторий: `INDEX.md` (какие скиллы есть),
  `step-N/README.md` (что делает шаг, когда какой скилл брать), `skills/*/SKILL.md` (сквозные скиллы).
  Есть подходящий скилл — подтянуть его, а не сочинять заново.
- Процесс: `git pull upstream main` → ветка `feature/*` → PR → мердж админом.
  В `main` не пушить, `--force-with-lease` вместо `--force`.
- Артефакты задач — только `tasks/<слаг>/…` на ветке `personal`; в `main` их не бывает.
- Публикация (коммит, push, PR) — только по прямой команде человека; сам не публикую.
- Не выдумывать цифры, требования и решения: нет данных — спросить человека.
- Нет скилла в репозитории — сказать прямо, не подставлять похожий по названию.
- Каждая задача в Jira, созданная с Hermes, помечается label `Hermes`.
- Секреты только в окружении: в репозитории и в remote URL токенов нет.
