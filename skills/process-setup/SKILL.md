# Настройка Гермеса под продуктовый процесс iiko

Одна процедура: от «есть доступ к репозиторию» до «можно вести задачу». Всё выполняется по шагам,
каждый проверяется. **Ничего не додумывать:** нет доступа, токена или MCP — спросить, а не обходить.

**Когда использовать:** первый запуск у продакта, «настрой процесс», «проверь, что настроено»,
переезд на новую машину.
**Когда не использовать:** настройка уже сделана (тогда `check-setup.sh` и сразу к задаче) или речь
про подключение одного скилла — это `git-skills-install`.

## Что должно быть до старта

| Нужно | Проверка | Если нет |
|---|---|---|
| Приглашение в организацию `iiko-product-process` (роль read) | `curl` на репозиторий отдаёт `200` | попросить администратора |
| Токен GitHub в `$HERMES_HOME/.env` (ключ `GITHUB_TOKEN`, бывает `GITHUB`) | `grep -E '^GITHUB' $HERMES_HOME/.env` | положить токен в `.env` |
| git и python3 | `git --version`, `python3 --version` | поставить |

## Шаги

### 1. Проверить доступ

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: token $(grep -E '^GITHUB(_TOKEN)?=' "$HERMES_HOME/.env" | cut -d= -f2- | tr -d '"')" \
  https://api.github.com/repos/iiko-product-process/iiko-product-process
```

`200` — доступ есть; `404` — приглашение не принято; `403` — токен без скоупа `repo`.

### 2. Клонировать репозиторий

```bash
git clone https://github.com/iiko-product-process/iiko-product-process.git ~/iiko_process
cd ~/iiko_process && git pull
```

Форков и пул-реквестов нет: репозиторий только читаем, обновления вносит администратор.

### 3. Поставить скиллы в Hermes

```bash
bash ~/iiko_process/skills/git-skills-install/scripts/install-skills-from-repo.sh --dry-run
bash ~/iiko_process/skills/git-skills-install/scripts/install-skills-from-repo.sh
```

Ожидаемо: `всего 38 | установлено … | пропущено 0`. После этого Гермес знает шаги и умеет ими
пользоваться. Повторять после каждого `git pull`.

### 4. Создать хранилище артефактов (Hermes wiki)

```bash
bash ~/iiko_process/skills/hermes-wiki/scripts/wiki-init.sh "$HOME/iiko_process/ARTIFACTS"
```

Появятся `~/iiko_process/ARTIFACTS/_шаблон` и `index.md` — внутри папки процесса, рядом со скиллами. Все артефакты задач — в `ARTIFACTS/<слаг>/`
(карточка, журнал, `01-проблема … 07-пилот`, `встречи/`, `материалы/`). В репозиторий артефакты не кладём.

### 5. Включить автообновление шага 4

```bash
bash ~/iiko_process/scripts/setup-design-cron.sh --repo ~/iiko_process
```

Скрипт ставит обёртку и печатает параметры cron. Создать задачу: расписание `0 6 * * 0`
(воскресенье, 09:00 МСК), режим **без агента**, скрипт `design-update-weekly.sh`.
Проверка: `bash ~/iiko_process/scripts/update-design-step.sh --dry-run`.

### 6. Подключить MCP — по одному, по мере надобности

| MCP | Что даёт | Без него |
|---|---|---|
| Atlassian (Jira + Confluence) | задачи PB, эпики/стори, публикация PRD, статусы | шаги 3, 5, 6 работают только руками |
| Pyrus | обращения клиентов из форм и реестров | шаг 1 без реальных жалоб |
| Matomo | цифры по iiko web, воронки, пути | шаг 1 без данных |
| Miro | доски, схемы | не критично |

Каждый проверяется пробным запросом (например, «покажи мои задачи в PB»). Токены — только в
`$HERMES_HOME/.env` или конфиге, в репозиторий и чат не вставлять.

### 7. Проверить, что всё сошлось

```bash
bash ~/iiko_process/scripts/check-setup.sh --repo ~/iiko_process
```

Чек-лист: клон, токен, скиллы (38/38), вики, обновление шага 4, MCP. Если есть строки «НЕТ» —
вернуться к соответствующему шагу.

### 8. Смоук-тест: понять, что Гермес действительно работает по процессу

Три короткие проверки — по одной на шаг:

| Проверка | Что сказать | Ожидаемо |
|---|---|---|
| Шаг 1 | «Вот сигнал: клиенты не находят блюдо в списке. С чего начать?» | Гермес берёт `problem-validation`, спрашивает сегмент и данные, предлагает карточку проблемы |
| Шаг 2 | «Сформулируй 3 гипотезы по этой проблеме» | формат «Если …, тогда …, так как …», метрика baseline → target |
| Шаг 3 | «Оформи стори по первой гипотезе» | `pb-task-writer`: вопросы по блокам, Epic/Story, label `Hermes` |

Если на любой вопрос Гермес отвечает «не знаю» или сочиняет формат — скиллы не установились
(вернуться к шагу 3).

## Первая настоящая задача

```bash
bash ~/iiko_process/skills/hermes-wiki/scripts/wiki-init.sh "$HOME/iiko_process/ARTIFACTS" --task <слаг-задачи>
```

Дальше — как обычно: шаг 1 (проблема) → 2 (гипотезы) → 3 (Story) → 4 (прототип) → 5 (PRD) → 6 (разработка).
Правила: артефакты в `ARTIFACTS/<слаг>/`, решения принимает человек, в Jira пишем только после
подтверждения, каждая созданная задача помечается label `Hermes`.

## Типовые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| `404` на репозиторий | приглашение не принято | принять приглашение в организации |
| `403` при клоне/чтении | токен без `repo` | перевыпустить токен, положить в `.env` |
| Скиллы не видны в чате | установка не выполнена или старый чат | `install-skills-from-repo.sh`, затем новый чат |
| `check-setup.sh` пишет «артефакты не найдены» | вики не создана | шаг 4 |
| Cron не создаётся | скрипт не в `$HERMES_HOME/scripts` | `setup-design-cron.sh` создаёт обёртку сам |
| MCP не отвечает | нет токена или сервер не запущен | проверить `.env`, перезапустить MCP |
