# Настройка Гермеса под продуктовый процесс iiko

Одна процедура: от «папка процесса подключена» до «можно вести задачу». Всё происходит в Hermes;
GitHub — источник обновлений, который ведёт администратор. Сотрудник с git не работает.

**Когда использовать:** первый запуск у продакта, «настрой процесс», «проверь, что настроено»,
переезд на новую машину.
**Когда не использовать:** настройка уже сделана (тогда `check-setup.sh` и сразу к задаче) или речь
про обновление одного скилла — это `git-skills-install`.

## Что должно быть до старта

| Нужно | Проверка | Если нет |
|---|---|---|
| Папка процесса в Hermes (скиллы, правила, `INDEX.md`) | в папке есть `INDEX.md` и `.hermes.md` | попросить администратора подключить |
| `ARTIFACTS` рядом с папкой процесса | `<папка>/ARTIFACTS/_шаблон` | создаётся на шаге 3 |
| Токены для MCP и API в `$HERMES_HOME/.env` | `grep -E '^GITHUB' $HERMES_HOME/.env` | положить токен в `.env`, в чат не вставлять |
| git и python3 в системе Hermes | `git --version`, `python3 --version` | поставить |

## Шаги

### 1. Проверить папку и правила

```bash
ls <папка процесса> | head
grep -c 'ARTIFACTS' <папка процесса>/.hermes.md
```

Правила из `.hermes.md` подхватываются автоматически: артефакты — в `ARTIFACTS`, правки общего слоя —
через администратора, решения принимает человек.

### 2. Поставить скиллы в Hermes

```bash
bash <папка процесса>/skills/git-skills-install/scripts/install-skills-from-repo.sh --dry-run
bash <папка процесса>/skills/git-skills-install/scripts/install-skills-from-repo.sh
```

Ожидаемо: `всего 37 | установлено … | пропущено 0`. После этого Гермес знает шаги и умеет ими
пользоваться. Повторять после каждого обновления папки процесса.

### 3. Создать хранилище артефактов

```bash
bash <папка процесса>/skills/hermes-wiki/scripts/wiki-init.sh "<папка процесса>/ARTIFACTS"
```

Появятся `ARTIFACTS/_шаблон` и `index.md` — внутри папки процесса, рядом со скиллами. Сотрудник
открывает одну папку и работает только в ней; в общий слой артефакты не попадают.

### 4. Включить джобы

```bash
bash <папка процесса>/scripts/setup-all.sh --repo <папка процесса>
```

Скрипт создаёт обёртки задач и печатает параметры:

| Джоба | Расписание | Скрипт |
|---|---|---|
| Обновление шага 4 | воскресенье, 09:00 МСК (`0 6 * * 0`) | `design-update-weekly.sh` |
| Сбор наработок | пятница, 10:00 МСК (`0 7 * * 5`) | `skills-collect-weekly.sh` |

Обе — в режиме «без агента»; пустой вывод = изменений нет.

### 5. Подключить MCP — по одному, по мере надобности

| MCP | Что даёт | Без него |
|---|---|---|
| Atlassian (Jira + Confluence) | задачи PB, эпики/стори, публикация PRD, статусы | шаги 3, 5, 6 работают только руками |
| Pyrus | обращения клиентов из форм и реестров | шаг 1 без реальных жалоб |
| Matomo | цифры по iiko web, воронки, пути | шаг 1 без данных |
| Miro | доски, схемы | не критично |

Каждый проверяется пробным запросом («покажи мои задачи в PB»). Токены — только в `$HERMES_HOME/.env`
или конфиге.

### 6. Проверить, что всё сошлось

```bash
bash <папка процесса>/scripts/check-setup.sh --repo <папка процесса>
```

Чек-лист: папка процесса, токен, скиллы (37), `ARTIFACTS`, обновление шага 4, MCP. Строки «НЕТ» —
вернуться к соответствующему шагу.

### 7. Смоук-тест: понять, что Гермес работает по процессу

| Проверка | Что сказать | Ожидаемо |
|---|---|---|
| Шаг 1 | «Вот сигнал: клиенты не находят блюдо в списке. С чего начать?» | берёт `problem-validation`, спрашивает сегмент и данные, предлагает карточку проблемы |
| Шаг 2 | «Сформулируй 3 гипотезы по этой проблеме» | формат «Если …, тогда …, так как …», метрика baseline → target |
| Шаг 3 | «Оформи стори по первой гипотезе» | `pb-task-writer`: вопросы по блокам, Epic/Story, label `Hermes`, `scoreWSJF` |

Если Гермес отвечает «не знаю» или сочиняет формат — скиллы не установились (шаг 2).

## Первая задача

```bash
bash <папка процесса>/skills/hermes-wiki/scripts/wiki-init.sh "<папка процесса>/ARTIFACTS" --task <слаг-задачи>
```

Дальше — по шагам: 1 (проблема) → 2 (гипотезы) → 3 (Story) → 4 (прототип) → 5 (PRD) → 6 (разработка).
Артефакты — в `ARTIFACTS/<слаг>/`, решения принимает человек, в Jira пишем только после подтверждения,
каждая созданная задача помечается label `Hermes`.

## Типовые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Скиллы не видны в чате | установка не выполнена | шаг 2, затем новый чат |
| `check-setup.sh` пишет «ARTIFACTS не найдена» | не создана | шаг 3 |
| MCP не отвечает | нет токена или сервер не запущен | проверить `.env`, перезапустить MCP |
| Джоба не создалась | скрипт не в `$HERMES_HOME/scripts` | `setup-all.sh` создаёт обёртку сам |
| В папке процесса появились личные файлы | артефакты положили не туда | перенести в `ARTIFACTS/<слаг>/` |

## Итоговое сообщение продакту

> Настройка готова: папка процесса подключена, 37 скиллов установлены, `ARTIFACTS` создана, джобы
> стоят на воскресенье и пятницу. MCP: ‹что подключено / что отложено›.
> Работаем в одной папке: сигнал → проблема → гипотезы → Story → прототип → PRD → разработка.
> С чего начнём: ‹проблема / гипотезы по готовой проблеме / оформить Story›?
