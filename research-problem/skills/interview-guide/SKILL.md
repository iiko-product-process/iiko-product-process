# Гайд интервью (скрипт встречи)

Второе действие исследования: из джобов и этапов пути собирается скрипт диалога. Эталон — «Гайд интервью» из обезличенного примера исследования (`research-problem/examples/primer-issledovaniya/notion-страница.md`). Типы вопросов для JTBD-логики — в `job-mapping/references/jtbd-method.md` (change / SWITCH).

## Сначала — цели

Перед вопросами зафиксировать: **«Цель интервью — узнать [X]»** и **«По результатам нужно понять: 1)… 2)…»**. Цели привязываются к задачам исследования; без них не собрать итог (см. `research-summary`).

## Правила составления (обязательные)

1. **Структура — по логике пользовательского пути в будущем продукте**, а не по приоритету вопросов. Каждый блок = этап, который человек пройдёт в продукте (пример: `Потребность → Поиск → Сравнение → Заказ → Получение → Оплата → Контроль`); внутри блока — вопросы о том, как этот этап устроен у него **сейчас**. У двустороннего продукта — отдельные версии гайда на каждую сторону (свой путь).
2. **Только реальный опыт.** Якорные формулировки: «Вспомните последний раз, когда…», «Расскажите, как это было», «Приведите пример».
3. **Никаких вопросов о будущем** («а если бы…», «стали бы вы…», «как должно быть», «что бы вы хотели»). Оценка будущего — отдельно, на прототипах.
4. **Никаких вопросов с ответом «да/нет»** — все вопросы открытые, на размышление и рассказ. Односложный ответ → «Почему?», «Что было дальше?», «Приведите пример».
5. **Ветки диалога.** Если ответ может пойти по-разному — показать продолжение для каждого варианта: «Ветка: [условие] → [вопрос-продолжение]».
6. **Ветки — с переносом строки** (чтобы читалось вживую на интервью): условие ветки на отдельной строке, вопрос-продолжение — на следующей; между ветками — пустая строка-разделитель.
7. **Покрытие джобов:** гайд проверяет **все** джобы — и «на уточнении», и уже подтверждённые (у последних убеждаемся, что поведение реально и больно). В блоках помечать: какие джобы проверяем, сигналы ✅ (подтверждение) и ⚠️ (риск/опровержение).
8. **Тест концепций — отдельная сессия**: в интервью не смешивать реальный опыт и оценку будущего.

## Каркас гайда

- **0. Интро (2 мин):** представление; конфиденциальность (цитаты без имён); «нет правильных ответов»; запись с согласия; для продукта с демонстрацией — сразу попросить показать экран («важно видеть не только что человек думает, но и как действует»).
- **1. Разогрев и профиль (5 мин):** роль, контекст, обычный день/неделя по теме.
- **Блоки по пути продукта (5–10 мин каждый):** цели блока (какие джобы проверяем) → вопросы о реальном опыте → ветки → сигналы ✅/⚠️.
- **Финал:** «Что я забыл спросить важного?», рекомендации знакомых, благодарность.
- **Приложения:** скрининг (единственное место, где допустимы фильтры «да/нет» — до интервью) и порядок обработки.
- **Пометки интервьюера** прямо в гайде курсивом (*пушить сюда*, *не забыть…*).

Пример оформления ветки:

```
> **Ветка:** искал(а) активно →
> «Где искали? Сколько заняло? Кто помогал?»
>
> **Ветка:** не искал(а) давно →
> «А кто из поставщиков появился у вас последним — как он к вам попал?»
```

## Приёмы модерации

- Смолл-ток → сложное; пауза после ответа; цитаты дословно; не продавать решение; можно отходить от скрипта за интересным инсайтом; копать «почему?» до глубинной мотивации.
- Если респондент сам уходит в будущее («вот если бы сервис умел…») — не обрывать, записать идею, вернуть к факту: «А как это устроено у вас сейчас? Последний пример?»
- По возможности закрывать 4 силы прогресса (Push / Pull / Fears / Habits) — почему меняют или не меняют поведение. Интервью 40–60 мин; запись с согласия.

## После интервью

- **Выжимки по респондентам** — таблицей по блокам гайда (`респондент | сегмент | сервисы/контекст | ответы по блокам`; в эталоне — `интервью-выжимки.csv`).
- Статусы: `назначено → проведено → обработано`; обрабатывать сразу после встречи; инсайты жирным, цитаты дословно.
- Отметить по блокам, какие джобы получили подтверждение/опровержение (карта покрытия и сигналы из гайда).
- После 2–3 интервью — ревизия гайда: убрать нерабочие вопросы, добавить всплывшие.
