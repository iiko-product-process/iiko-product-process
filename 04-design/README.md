# Шаг 4 — «Дизайн»

Папка шага 4 — **точная копия двух репозиториев дизайн-команды**, без переупаковки. Ничего не
переименовывается и не раскладывается по-своему: как у дизайнеров, так и здесь.

| Папка | Источник | Что внутри |
|---|---|---|
| `Design-System/` | [iiko-DS/Design-System](https://github.com/iiko-DS/Design-System) | дизайн-система: `components-web/`, `components-mobile/`, `molecules/`, `organisms/`, `connect.js`, `dsr-assets/`, `ds-review.*`, `fixes.md`, `UX-памятка_расположение-элементов.md`, `start-here.md` |
| `Prototype-Guide/` | [iiko-DS/Prototype-Guide](https://github.com/iiko-DS/Prototype-Guide) | гайд и инструменты: `prototyping-guide/` (`01-начало … 07-архив`, `дизайн-система`, `подключение-ds.md`, `04-агенты` со скиллами ДС), `demo-connect.html`, `device-chrome/`, `ds-frame-nav.js`, `ds-sizes-toggle.js`, `layouts.js`, `touch-mode.*`, `review-notes.md` |
| `skills/ux-writing-iiko.md` | наш скилл | тексты интерфейса: генерация, ревью, консультации |

Актуальность: **обновляется автоматически** — админский cron каждую субботу синхронизирует копии с
репозиториями дизайнеров и коммитит в `main`; у сотрудников cron каждое воскресенье обновляет папку
из GitHub. Руками копии не правим: правка уйдёт при следующем обновлении.

## Что можно сделать

- **Собрать прототип по гайду** — `Prototype-Guide/prototyping-guide/подключение-ds.md`: страница
  подключает ДС **одной строкой** (`connect.js`), собирается из компонентов `ds-*`.
- **Написать и проверить тексты** — скилл `skills/ux-writing-iiko.md`.
- **Показать прототип** — `Prototype-Guide/demo-connect.html`, `device-chrome/`, `touch-mode.css`,
  `ds-frame-nav.js`, `ds-sizes-toggle.js`.
- **Работать без интернета** — компоненты и токены лежат локально в `Design-System/`.
- **Понять правила ДС** — `Design-System/fixes.md` (журнал правок), `Design-System/UX-памятка_расположение-элементов.md`,
  `Prototype-Guide/prototyping-guide/04-агенты/AGENTS.md`.

## Два режима работы

**A. VS Code** — ДС и прототип в одном окне:

1. `code <репозиторий>/04-design` — открывается папка шага;
2. `File → Add Folder to Workspace…` → `ARTIFACTS/<слаг>/04-дизайн` — папка артефактов задачи;
3. расширение **Live Server** → «Go Live» для предпросмотра;
4. прототип лежит в папке задачи и ссылается на ДС через `connect.js`;
5. `Design-System/` и `Prototype-Guide/` — только чтение: это копии чужих репозиториев.

**B. Standalone** — один HTML-файл, работает без интернета:

1. основа — `Prototype-Guide/demo-connect.html`;
2. убрать `<script src="…/connect.js">`, вместо него `<style>` с содержимым
   `Design-System/components-web/tokens.css`, `Design-System/components-web/fixes.css` и CSS нужных
   компонентов (`Design-System/components-web/components/<Имя>_DS/*.css`), для мобильных —
   `Design-System/components-mobile/modes.css`;
3. иконки: ссылка на Material Icons (нужен интернет) или инлайн-SVG;
4. проверить `grep -n "https\?://" прототип.html` — ссылок на ДС быть не должно;
5. сохранить в `ARTIFACTS/<слаг>/04-дизайн/`.

## Автообновление

| Где | Когда | Что делает |
|---|---|---|
| Аккаунт администратора | суббота, 10:00 | `scripts/sync-design-repos.sh`: тянет оба репозитория дизайнеров, заменяет копии в `04-design/`, коммитит и пушит `main`; затем переустанавливает скиллы |
| Машина сотрудника | воскресенье, 09:00 | `scripts/update-design-step.sh`: `git pull` и обновление папки шага + переустановка скиллов, чтобы в понедельник была свежая ДС |

Ручной запуск:

```bash
bash scripts/sync-design-repos.sh --dry-run     # админ: показать, что изменится
bash scripts/update-design-step.sh --dry-run    # сотрудник: проверить, есть ли обновления
```

## Когда брать какой скилл

| Скилл | Когда использовать | Когда не использовать |
|---|---|---|
| `iiko-design-system` | Работа в репозиториях ДС: токены, режимы, мобильные варианты, устройство системы | Собирается обычная страница — хватает гайда и `ux-writing-iiko`; нужна правка компонента — `iiko-ds-components` |
| `iiko-ds-components` | Правим или собираем конкретный компонент: CSS, токены, режимы, классы | Вопрос про принципы системы — `iiko-design-system`; прототип не трогает ДС |
| `ux-writing-iiko` | Тексты интерфейса: сгенерировать для прототипа, отревьюить формулировки | Правки визуала без текста; тексты для маркетинга |

## Связь с другими шагами

- **Вход:** Story из шага 3 (сценарии, критерии приёмки) + данные и гипотезы из шагов 1–2.
- **Выход:** прототип и утверждённые тексты — в шаг 5 (PRD) и шаг 6 (реализация).
- **Не входит:** продуктовые решения (продакт), технические маппинги (шаг 5).
