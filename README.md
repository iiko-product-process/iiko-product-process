# Продуктовый процесс iiko

Канон: **https://github.com/iiko-product-process/iiko-product-process** (private, организация `iiko-product-process`).

Репозиторий продуктового процесса iiko web: скиллы по шагам, реестр скиллов, шаблон задачи и правила работы.

## Что внутри

| Папка | К чему относится |
|---|---|
| `step-1-problem/` | Шаг 1 — проблема: формулировка, валидация, исследование, рынок, данные |
| `step-2-hypotheses/` | Шаг 2 — гипотезы, приоритизация, ICE |
| `step-3-pb-task-writer/` | Шаг 3 — задача в Jira PB |
| `step-4-design/` | Шаг 4 — дизайн, прототипы, гайды |
| `step-5-specification/` | Шаг 5 — спецификация (PRD) |
| `step-6-development/` | Шаг 6 — разработка: выгрузка задач Jira, актуализация требований |
| `step-7-pilot/` | Шаг 7 — пилотирование и запуск в прод (папка создана, наполняется) |
| `skills/task-workspace/` | Сквозной скилл ведения папки задачи (канон) |
| `skills/share-to-common/` | Сквозной скилл «поделиться с командой»: собрать предложение и отправить PR |
| `skills/mirror-skill-to-repo/` | Сквозной скилл «новый скилл → в репозиторий»: предложить зеркалировать локальный скилл в папку шага |
| `INDEX.md` | Реестр всех скиллов процесса: на каждый скилл обязательна строка |
| `CONTRIBUTING.md` | Процесс работы: форк → ветка → PR |

## Две ветки

| Ветка | Назначение | Что лежит |
|---|---|---|
| `main` | Общее, единственный источник для команды | Скиллы `step-N/…`, `skills/task-workspace`, `INDEX.md`, README, CONTRIBUTING |
| `personal` | Личное пространство сотрудника | **Все артефакты**: `tasks/README.md`, `tasks/_шаблон` и папки задач `tasks/<слаг>/` |

## Как начать

1. **Fork** канона в свой аккаунт — доступ выдан только на чтение, форк разрешён.
2. Клонируй свой форк и подключи канон как `upstream`:

```bash
git clone https://github.com/<ты>/iiko-product-process.git
cd iiko-product-process
git remote add upstream https://github.com/iiko-product-process/iiko-product-process.git
```

3. Обновляй общее: `git checkout main && git pull upstream main`.
4. Личные задачи веди на ветке `personal` — она не PR-ится никогда.
5. Предложить общий скилл — ветка `feature/*` от чистого `main` → PR в `main` канона, мержит админ.

Полный процесс — [CONTRIBUTING.md](CONTRIBUTING.md). Реестр скиллов — [INDEX.md](INDEX.md).

## Как предложить идею в общую папку

Если появилась наработка, которой должны пользоваться все — скилл, шаблон, документ шага, правка
общего скилла — она попадает в `main` только через PR. Разбираться в git для этого не нужно: в Hermes
есть скилл [`skills/share-to-common/`](skills/share-to-common/SKILL.md), который собирает предложение
и отправляет PR сам.

Достаточно сказать в чат одну из фраз: «добавь в общую папку», «чтобы видели все», «хочу поделиться
со всеми», «сделай общим», «пусть это будет в процессе у всех». Дальше чат предложит оформить PR,
соберёт ветку `feature/*` от свежего `main`, запушит в ваш форк и откроет пул-реквест.

Правила мерджа коротко (полностью — [CONTRIBUTING.md](CONTRIBUTING.md)):

| Что | Правило |
|---|---|
| Кто отправляет | автор идеи, из своего форка, ветка `feature/*` от свежего `main` |
| Что в PR | одна идея = одна ветка = один PR; скилл + строка в `INDEX.md` + поднятый `version:` |
| Что не в PR | артефакты задач (`tasks/**`), черновики, токены, большие бинарники |
| Кто мержит | админ репозитория, апрув с другого аккаунта (автор ≠ мержащий) |
| Как мержится | squash and merge, один коммит; ветка `feature/*` удаляется |
| Прямой push в `main` | невозможен: у участников роль read, изменения только через PR |

## История

Снимок-объединение двух процессных репозиториев (`iiko-product-process-main` + `iiko-product-process`) от 19.10.2026: общее вынесено в `main`, личные папки задач — в `personal`. Тогда же репозиторий перенесён в организацию `iiko-product-process`: участники получают доступ только на чтение и работают через форки.

История git начинается с этого снимка — правки до 19.10.2026 в ней не отражены. С этого момента каждая правка скилла — отдельный коммит с сообщением «что изменено», поэтому откатить правку можно через `git revert` или `git checkout <sha> -- <путь>`.

## Версии

У каждого скилла в frontmatter есть `version:`. Правило: содержательная правка скилла → поднять версию (patch для уточнений, minor для новых шагов работы), новая запись в `INDEX.md` — если меняется состав скиллов.
