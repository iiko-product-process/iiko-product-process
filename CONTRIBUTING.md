# Как работать с процессом iiko

Всё происходит внутри Hermes: есть папка процесса (скиллы, правила, README шагов) и `ARTIFACTS`
(артефакты задач). Отдельного рабочего места в GitHub у сотрудника нет.

| Что | Где | Кто меняет |
|---|---|---|
| Скиллы, шаблоны, правила, README шагов | папка процесса в Hermes | администратор |
| Артефакты задач (карточка проблемы, гипотезы, Story, PRD, прототипы, транскрипты, встречи) | `ARTIFACTS/<слаг>/…` внутри папки процесса | сотрудник |

Папку процесса подключает и обновляет администратор. Сотрудник ничего не настраивает в GitHub,
не создаёт личных копий и не публикует артефакты — они живут только в `ARTIFACTS`.

## 1. Первая настройка

```bash
bash <папка процесса>/scripts/setup-all.sh --repo <папка процесса>
```

Скрипт ставит скиллы, создаёт `ARTIFACTS`, обёртки задач и проверяет результат. В конце —
`scripts/check-setup.sh`: папка, токен, скиллы, `ARTIFACTS`, обновление шага 4, MCP.

## 2. Как обновляется папка процесса

Обновления приходят от администратора: он вносит правки и обновляет папку. У сотрудника раз в неделю
работает джоба, которая подтягивает свежую версию и переустанавливает скиллы — в понедельник свежая
дизайн-система и актуальные скиллы.

## 3. Где вести задачу

Каждая задача — папка `ARTIFACTS/<слаг>/`:

```
ARTIFACTS/<слаг>/
  README.md         карточка: статус, текущий шаг, кто ведёт, ссылки
  журнал.md         дата · что сделали · артефакты · кто
  01-проблема/      02-гипотезы/   03-требования/   04-дизайн/
  05-спека/         06-реализация/ 07-пилот/         материалы/  встречи/
```

Каркас создаётся скиллом `hermes-wiki` (или `task-workspace`). Крупные файлы — прототипы, таблицы,
pdf — кладутся в раздел шага, а не в корень.

## 4. Как предложить идею в общий слой

Скажи в чат «поделись с командой», «добавь в общую папку», «чтобы видели все» — скилл
`share-to-common` соберёт пакет (файл + 2–3 строки «зачем») и передаст администратору. Он проверит,
внесёт в общий слой, обновит `INDEX.md` и версию; команда получит это со следующим обновлением.

| Что | Правило |
|---|---|
| Кто отправляет | автор идеи, прямо из чата |
| Что в предложении | один скилл или одна правка + строка «зачем» |
| Что не отправляется | артефакты задач, личные черновики, токены, большие бинарники |
| Что делает админ | проверяет, вносит, обновляет `INDEX.md` и версию |

## 5. Чего не делаем

- Не создаём личных копий папки процесса и не работаем в GitHub.
- Не публикуем артефакты задач: они остаются в `ARTIFACTS`.
- Не правим скиллы в папке процесса — предложение уходит администратору.
- Не вставляем токены в чат, скиллы и артефакты: только `$HERMES_HOME/.env`.

## 6. Где что лежит

| Что | Где |
|---|---|
| Скиллы шагов | `01-research-problem/`, `02-hypotheses/`, `03-story/`, `04-design/`, `05-specification/`, `06-development/`, `07-pilot/` |
| Сквозные скиллы | `skills/<имя>/` |
| Реестр скиллов | `INDEX.md` |
| Артефакты задач | `ARTIFACTS/<слаг>/` |
| Скрипты обслуживания | `scripts/` |
| Правила процесса | `.hermes.md`, этот файл |
