# Как работать с репозиторием iiko-product-process

Канон — [iiko-product-process/iiko-product-process](https://github.com/iiko-product-process/iiko-product-process).
Один репозиторий, одна ветка `main`, доступ у сотрудников — **только чтение**.

| Что | Где | Кто меняет |
|---|---|---|
| Скиллы, шаблоны, правила, README шагов | репозиторий, ветка `main` | администратор процесса |
| Артефакты задач (карточка проблемы, гипотезы, Story, PRD, прототипы, транскрипты, встречи) | **Hermes wiki**, папка `Задачи/<слаг>/…` | сотрудник |

**Форков и PR нет.** Сотрудник ничего не пушит и не открывает пул-реквестов: репозиторий обновляет
администратор, артефакты живут в вики. Это сделано намеренно — чтобы не учить людей git.

## 1. Первый раз: клон

```bash
git clone https://github.com/iiko-product-process/iiko-product-process.git
cd iiko-product-process
```

Если репозиторий приватный, git спросит токен: используется тот, что лежит в `$HERMES_HOME/.env`
(ключ `GITHUB_TOKEN`, на части машин `GITHUB`). Форк не нужен.

## 2. Как обновляться

```bash
git pull
```

Обновления вносит администратор — сам, в `main`. После обновления повтори установку скиллов, чтобы
Hermes увидел изменения:

```bash
bash skills/git-skills-install/scripts/install-skills-from-repo.sh
```

Установщик не перезаписывает скиллы, которые правили руками: такие попадают в отчёт как «пропуск».

## 3. Где вести задачу

**Не в репозитории.** Каждая задача — папка в Hermes wiki:

```
Задачи/<слаг>/
  README.md        карточка задачи: статус, текущий шаг, кто ведёт, ссылки
  журнал.md        история работ: дата · что сделали · артефакты · кто
  01-проблема/  02-гипотезы/  03-требования/  04-дизайн/
  05-спека/  06-реализация/  07-пилот/
  материалы/  встречи/
```

Правила ведения папки — скилл `task-workspace`. Рабочую папку можно держать где удобно, а в вики
переносить скриптом:

```bash
python3 skills/task-workspace/scripts/sync-task.py \
  --from ~/work/PB-7105-nacenka \
  --task "<wiki>/Задачи/pb-7105-nacenka" --dry-run
```

## 4. Как предложить идею в общий слой

Если появился скилл, шаблон или правка, которые нужны всем:

1. сказать в чат «поделись с командой» / «добавь в общую папку» / «чтобы видели все»;
2. скилл `share-to-common` соберёт пакет (файл + 2–3 строки «зачем») и отправит администратору —
   в общую папку или в Telegram;
3. администратор смотрит и вносит сам: правит репозиторий и обновляет `INDEX.md`.

Никаких веток и пул-реквестов для этого не требуется.

**Что стоит предлагать:** новый скилл, шаблон, документ шага, исправление ошибки, удачный промпт.
**Что не надо:** артефакты задач, личные черновики, `.env` и токены, большие бинарники.

## 5. Правила, которые проверяет администратор

- новый скилл — строка в `INDEX.md` и папка шага по теме;
- у изменённого скилла поднят `version:`;
- в репозитории нет артефактов задач и секретов;
- описание скилла начинается с «Use when …» — по нему Hermes решает, когда его брать.

## Где что лежит

| Место | Что |
|---|---|
| `01-research-problem/` … `07-pilot/` | скиллы и документация шагов |
| `skills/` | сквозные скиллы (папка задачи, обмен, установка, сбор наработок, онбординг) |
| `INDEX.md` | реестр всех скиллов |
| `.hermes.md` | правила для Гермеса, действуют при работе в папке |
| Hermes wiki → `Задачи/<слаг>/` | артефакты задач |
