# Промпт к прототипу: «Продукты» — закупки ресторана (первая версия)

> Промпт для воссоздания прототипа пользовательского пути в другой LLM/Coding-агенте.
> Самодостаточен: не требует истории общения. Пиксельное совпадение не требуется; обязательны структура, поведение и ключевые элементы.
> Связанные материалы: PRD «Закупочная платформа „Продукты“ — первая версия» (05-спека), прототип `produkty-zakupki-mvp.html` (04-дизайн).

## Контекст

Сделай кликабельный HTML-прототип **одной страницей** (self-contained) для продукта **«Продукты» — закупочная платформа для ресторанов** (первая версия, пилот).
Пользователи: **закупщик ресторана** и **сотрудник поставщика**. Назначение прототипа — показать весь пользовательский путь (ресторан + поставщик + альтернативы) на одном экране для ревью и согласования до разработки.

## Что построить (структура страницы)

1. **Верхняя панель ревью** (обвязка, отделена от продукта):
   - заголовок «Продукты · закупки ресторана (MVP)»;
   - кнопка «Подсказки ДС» (раскрывает список пробелов, найденных при сборке; у тебя список может быть пустым — оставь кнопку и короткий текст);
   - стрелки ← →, выпадающий список всех состояний (сгруппирован: «Ресторан · …», «Поставщик») и счётчик «N / 19».
2. **Блок-пояснение** под панелью: для каждого состояния — группа, заголовок, «Что на экране: …», «Почему так: …».
3. **Кадр приложения**: шапка (лого iiko, выбор ресторана «Romashka OOO», периодные табы, колокольчик, пользователь) и левая рельса-меню (иконки). Если воспроизводишь без реальной ДС — нарисуй упрощённо, главное — сохранить расположение и узнаваемость.
4. **Рабочая область** — контент состояния (описания ниже).

## Технические требования

- Один файл HTML, без сборки и зависимостей; интерактив — на ванильном JS.
- Режим ревью: `?state=<id>` открывает состояние напрямую; `?ui=0` скрывает панель ревью и пояснение; `?hints=1` раскрывает подсказки; стрелки ← → переключают состояния.
- Переходы по клику: у кнопок/строк атрибут `data-go="<id>"` — переход на состояние; живые действия (переключение статуса, отправка КП) меняют текущее состояние без перехода.
- Стиль: светлый фон #f4f5f7, карточки белые с рамкой и скруглением 12, шрифт Roboto, акцент синий #448AFF, успех зелёный, предупреждение оранжевый. Ощущение — «взрослый» B2B-интерфейс iiko: таблицы, списки, статусы-чипы, аккуратные отступы.
- Виджеты (если доступна дизайн-система iiko — используй её компоненты; если нет — воспроизведи похожими по смыслу):
  - таблица (шапка + строки, выравнивание чисел вправо);
  - список (строка: текст + подпись, справа значение или кнопка);
  - карточка с заголовком и футером;
  - статус-чип (цветной: путь/подтверждён/доставлен/предупреждение);
  - кнопки: основная (синяя), вторичная (с рамкой), текстовая; группа кнопок;
  - поиск-строка с иконкой; поле ввода с рамкой; чекбокс; разделители между строками.
  - боковая панель (drawer): справа поверх экрана, ширина ~60% (920px), без затемнения фона; внутри — карточки-варианты с кнопками действий; закрытие крестиком и кликом вне панели.
- Косяки обвязки: если у контейнера списка зашита фиксированная ширина (в ДС iiko — width:258px и min-height:257px) — снять и растянуть на всю ширину карточки; строки списков прижимать на всю ширину. У разделителя внутри карточки нет вертикальных отступов — задавать (≈12px), иначе «слипается» с соседями.
- Карточки в двухколоночных экранах: заголовок — над карточкой (h2 16 medium) в строке высотой 40px; строки с кнопкой и без — одной высоты, иначе карточки «разъезжаются» по вертикали. Внутренние отступы карточки — 16px; карточки-спутники («Итого», «Запрос», «Поставка») — всегда с заголовком.
- Пустые состояния: иконка + пояснение + действие (пример: «Ничего не найдено: измените запрос или выберите категорию»).
