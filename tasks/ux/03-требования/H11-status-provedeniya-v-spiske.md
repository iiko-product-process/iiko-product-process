## Цель

Показать в списке документов, что проведено, что нет и каких полей не хватает, чтобы не открывать каждую накладную ради проверки.

## AS-IS

- 709 из 1 166 визитов раздела (60,8%) заканчиваются на рабочем экране; 282 из 894 визитов с накладной (31,5%) — на ней.
- Медиана на экране накладной — 84 с, p90 — 377 с; 61% замеров дольше 60 с.
- 85,0% обрывов — на компьютере; доля обрыва почти равна (60,7% / 59,9%) — устройство не причина, проблема в форме и статусах.

## TO-BE

- В списке документов — колонки: «Статус» (проведён/черновик/ошибка), «Не хватает полей», дата/сумма.
- Фильтр «Не проведены» и «С ошибкой».
- Из списка видно, почему документ не проведён; клик открывает документ на проблемном поле.
- Статус обновляется после проведения без перезагрузки списка.
- Для больших списков — быстрый рендер/пагинация.

## Пользовательский путь

```text
Документы → список
└─ действие: просмотр списка
   └─ элемент: статус + недостающие поля
      └─ цель: понять, что не проведено и почему
         ├─ далее: открыть документ на проблемном поле
         └─ альтернатива: фильтр «Не проведены» → массовое проведение (H13)
Накладная
└─ действие: проведение
   └─ элемент: ошибка/успех
      └─ цель: завершить
         └─ далее: список со статусом
```

## Сценарий (Given / When / Then)

**Дано:** В списке документов есть непроведённые накладные.  
**Когда:** Пользователь открывает список или фильтр «Не проведены».  
**Тогда:** Видит статус и причину, может открыть документ сразу на проблемном поле.

## Критерии приёмки

- У каждого документа в списке есть статус проведения.
- Для непроведённых видна причина/список недостающих полей.
- Фильтры «Не проведены» и «С ошибкой» работают.
- Клик по проблеме открывает документ на нужном поле.
- Статус совпадает с фактическим проведением, без ложных «Проведён».
- Список работает на 1 000+ документов без заметной деградации.

## Где проявляется

Документы → список / входящая накладная. 85,0% обрывов — компьютер; проверять на компе.
