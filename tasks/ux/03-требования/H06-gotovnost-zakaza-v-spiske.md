## Цель

Показать в списке заказов, какие заказы не готовы к работе и каких полей не хватает, чтобы не открывать карточку ради проверки.

## AS-IS

- 489 из 3 706 визитов раздела (13,2%) заканчиваются на карточке; 487 из 2 538 визитов с карточкой (19,2%) не возвращаются к списку.
- 2 175 визитов — цикл «список → карточка → список», 21 527 вхождений; 1 774 — повторный вход в карточку.
- 88,3% обрывов — на компьютере; доля обрыва 22,1% на компе против 2,7% на мобильном; 42,0% визитов раздела — мобильные.

## TO-BE

- В списке заказов — колонка/бейдж «Готовность»: «Готов», «Не хватает полей», «Ошибка».
- Видно, каких обязательных полей не хватает (кратко, по клику — подробно).
- Фильтр «Не готовы» и сортировка по готовности.
- Переход в карточку — сразу к первому незаполненному полю.
- Готовность не врёт: рассчитывается по тем же правилам, что и сохранение.

## Пользовательский путь

```text
Закупки → список заказов
└─ действие: просмотр списка
   └─ элемент: бейдж «Готовность» + причина
      └─ цель: понять, какие заказы можно запускать
         ├─ далее: фильтр «Не готовы» → карточка к нужному полю
         └─ альтернатива: массовое редактирование (H08)
Карточка заказа
└─ действие: сохранение
   └─ элемент: ошибка обязательного поля
      └─ цель: быстро исправить
         └─ далее: возврат к списку с сохранённым фильтром (H07)
```

## Сценарий (Given / When / Then)

**Дано:** В списке заказов есть заказы с незаполненными обязательными полями.  
**Когда:** Пользователь открывает список или применяет фильтр.  
**Тогда:** Видит готовность каждого заказа и может открыть карточку сразу на проблемном поле.

## Критерии приёмки

- У каждого заказа в списке есть статус готовности.
- Для «Не готов» видна причина/список недостающих полей.
- Фильтр «Не готовы» работает и сохраняется при возврате.
- Клик по проблеме открывает карточку на нужном поле.
- Статус совпадает с результатом сохранения (нет ложных «Готов»).
- Список не деградирует по скорости на 1 000+ заказов.

## Где проявляется

Закупки → список заказов / карточка. Основные обрывы — компьютер (88,3%), мобильный — 42,0% визитов; проверять оба, начинать с компьютера.

## Out of Scope

- Массовое редактирование заказов — H08.
- Автозаполнение полей.
- Пересчёт цен/скидок.

## Что нужно уточнить у PO

1. Какие поля обязательны для каждого типа заказа?
2. Можно ли считать готовность на бэкенде и отдавать в списке?
3. Нужен ли пересчёт при изменении шаблона заказа?
