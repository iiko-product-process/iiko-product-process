# JTBD: методика и шаблоны (конспект)

**Источники:**
- Статья «Практика Jobs To Be Done на человечках» — https://habr.com/ru/articles/704812/ (Виктор Бутенко, @stickmanpm). Теория — первая часть «Теория Jobs to be Done на человечках».
- Шаблоны скриптов интервью (гугл-таблица автора): https://docs.google.com/spreadsheets/d/1hH9r2802LAeSkqZhF4ppJiFmX2xVSHSHUl1iVK4GCQM/edit — листы: `info` (пошаговый гайд), `first hire`, `change`, `SWITCH`, `ODI` (пусто), `change all`.
- Доп.: Ульвик (ODI), Клемент, Кальбах; по-русски — Дмитрий Капаев, Юрий Дроган.

## Ключевые понятия
- **Main job** = глагол + существительное + пояснение («Закупить продукты для кухни»). Уровни абстракции: функциональные (Ульвик) / эмоциональные (Клемент); поднять уровень — вопросом «Чтобы что?».
- **Job Story**: «Когда… (точка А) — Я хочу… (работа) — Чтобы… (точка Б)». Гипотетические job stories можно составлять до исследования.
- **Job map / JTBD Canvas** — визуализация (автор делает стикерами в Miro).

## Типы JTBD-интервью (выбор по цели)
| Тип | Когда подходит | Что даёт |
|---|---|---|
| **First hire** | новая работа на рынке / сегмент ещё не выполнял работу | контекст возникновения работы, мотивация, метрики принятия решения |
| **Change** | продукт-оптимизатор для тех, кто давно выполняет работу | как определяют работу, какие решения «нанимали» и почему, 4 силы прогресса (Push/Pull/Anxiety/Habit), метрики |
| **SWITCH** | нужно детально понять процесс этапа | первая мысль → пассивный поиск → активный поиск → выбор и покупка → потребление → удовлетворённость → смена решения |
| **ODI** | много needs для количественного этапа | (шаблон в таблице автора пока пустой) |

Для вывода нового продукта/платформы на существующий рынок — **Change** (+ блок SWITCH-вопросов для деталей процесса).

## Этапы процесса исследования (лист `info`)
Цель → задачи интервью → тип интервью → ЦА (ценнее те, кто работу уже выполнял) → квалификационный опросник → скрипт → поиск ЦА → договорённость → интервью → следующий шаг/фидбэк → обработка → обновление методики.

- **Опросник:** ≤3 мин; контакты в конце; телефон/мессенджеры (email — ниже конверсия); спрашивать интенсивность выполнения работы и свежесть («как давно меняли решение»).
- **Где искать ЦА бесплатно:** тематические чаты/форумы, свои базы, LinkedIn и профильные площадки, у конкурентов (отзывы), нетворк. Платно: adsrecruiting, uxssr, Respondent.io. В последнюю очередь — продуктовые чаты рисерчеров.
- **Договорённость:** calendly+zoom; предлагать «сегодня–завтра»; время ≤40–60 мин; что-то дать взамен (скидка/бонус, не обязательно деньги).

## Структура скрипта (каркас, адаптируется)
Саммари · статус анкеты (`назначено / проведено / обработано`) · ссылка на запись → Интро (кто мы, зачем, спросить про запись) → Разогрев («расскажите про себя») → Профиль из опросника → Main job → Контекст работы → Триггер к поиску → Поиск решения → Покупка решения → Конкуренты текущие/потенциальные → Push / Pull / Fears & Anxiety / Habits → Бюджет → Метрики успешного решения → Заключение («что забыл спросить?», рекомендации знакомых, вознаграждение).

Полные вопросы — в листах `first hire` / `change` / `SWITCH` гугл-таблицы (и в сохранённой копии в задаче).

## Правила интервью (кратко)
Смолл-ток → сложное; копать «почему»; открытые вопросы; слушать, не перебивать, держать паузы; не предлагать готовых ответов; не спрашивать про будущее («если бы») — только прошлый опыт; не продавать своё решение; можно отходить от скрипта; запись + камера/ассистент.

Примеры: Плохо «Как сделать сервис лучше?» / «Важно ли, сколько позиций в фильтре?» → Хорошо «Опишите последний опыт использования фильтров. Какие были проблемы?».

## Обработка
Сразу после интервью; главные инсайты жирным; прямые цитаты (годятся в маркетинг); Miro-карта (JTBD Mapping); задачи ставить сразу; **не экстраполировать** качественные данные — валидировать количественно (ODI: важность × удовлетворённость).

## Технические заметки

- Разбор `.xlsx` без openpyxl и грабли (самозакрывающиеся ячейки съедают вопросы) — `scripts/xlsx_dump.py` этого скилла.
