# Действие 3: конкурентный анализ (шаг 1)

Третье из четырёх действий шага 1 (навигатор — скилл `problem-validation`). Задача — найти и зафиксировать примеры решений конкурентов по задаче проблемы.

## База конкурентов

Живёт в файле этого скилла: `references/competitors.md` (в репозитории — `iiko-product-process/step-1-problem/skills/competitor-analysis/references/competitors.md`). Стартовый список: **R-keeper, Рестик, Атол Sigma Еда, Эвотор, Контур Общепит, QuickResto, Мой Кассир, Saby (СБИС)** — дополнять.

Правило: **сначала смотри базу** (дешёвые модели находят примеры без похода на сайты), а после нового анализа — дописывай в неё, чтобы она росла.

## Как проводить

1. Сформулируй задачу от проблемы: какой раздел/сценарий смотрим.
2. По каждому конкуренту зафиксируй по формату (он же формат базы):
   ```
   ### <Конкурент> · <раздел/задача>
   - Задача: <какую задачу решает пользователь>
   - Решение: <как реализовано: экран, шаги, элементы>
   - Чем отличается от нашего: <…>
   - Источник: <ссылка> · <дата проверки>
   - Применимость: <что можно взять в гипотезы>
   ```
3. Смотреть решения — где можно: сайты/демо/справка/витрины приложений (браузером агента), статьи, обзоры. Скриншоты — ссылками (файлами не храним).
4. Итоги — в карточку проблемы, раздел **«5. Конкуренты: примеры решений»** (таблица `Конкурент | Задача | Как решено | Источник | Дата`).
5. Дописал базу — коммит (канон в репозитории) + строка в `журнал.md` задачи.

## Промпт-рамка для поиска

```
Контекст: [продукт, раздел, сегмент].
Проблема: [формулировка].
Ищем: решения конкурентов для [задача раздела].
Ограничения: только [список конкурентов/источников]; не предлагать решения; по каждому пункту — ссылка и дата.
Формат: таблица «конкурент | как решено | чем отличается | применимость».
```
