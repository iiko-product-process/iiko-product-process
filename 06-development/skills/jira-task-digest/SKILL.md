# Выгрузка по задаче Jira: что делает техкоманда (шаг 6)

## Overview

Скилл отвечает на вопрос «что сейчас происходит с эпиком / стори / задачей» одной выгрузкой: собирает всю семью задач вокруг указанной, их статусы, ответственных, даты и последние изменения — и отдаёт дайджест, по которому можно задавать вопросы, не переходя между разделами Jira и не собирая статусы вручную.

Это рабочий инструмент продакта во время разработки: сначала посмотреть состояние, потом решить, что менять в описаниях (для этого есть скилл `requirement-actualization`) и что зафиксировать в эпике.

Работает скриптом `scripts/jira_task_digest.py` (Jira REST API v2, без зависимостей). Скилл вызывается по ссылке на задачу или по ключу и **только читает**: в Jira он ничего не пишет.

## When to Use

- «что происходит по PB-7986», «какие статусы у задач эпика», «где застряло», «что делает техкоманда по этой задаче»;
- прислали ссылку на задачу Jira и хотят понять состояние работ по ней и вокруг неё;
- нужно раз в день/неделю отслеживать движение по эпику (регулярный режим, cron);
- перед встречей с командой — собрать «что изменилось с прошлой выгрузки».

Если просят **изменить требования** по итогам разработки — это второй скилл, `requirement-actualization`.

## Перед запуском

```bash
source /opt/data/.env          # JIRA_TOKEN
JIRA_URL по умолчанию https://jira.iiko.ru
```

Скрипт в репозитории: `06-development/scripts/jira_task_digest.py` (копия лежит рядом со скиллом — `jira_task_digest.py`).
**Куда складывать артефакты.** Как и у остальных шагов процесса — в папку задачи: `ARTIFACTS/<слаг>/06-реализация/` (слаг задачи в репозитории процесса). Имена файлов:

* `digest-<KEY>-<дата>.md` — выгрузка, `snapshot-<KEY>-<дата>.json` — снапшот для диффа со следующей выгрузкой;
* в режиме спринта вместо ключа идёт `sprint-<доска>`, а в имени папки задачи — слаг задачи команды.

Папки задачи ещё нет → завести её скиллом `task-workspace` (или сказать об этом и не складывать файлы в папку шага). В самой папке шага 6 лежат только скиллы, скрипты и README — артефакты по задачам там не хранятся. После раскладки — строка в `журнал.md` задачи, коммит и пуш.

## Порядок работы

1. **Взять ключ.** Из ссылки (`https://jira.iiko.ru/browse/PB-7986`) или из слов пользователя. Нет ключа — спросить, не угадывать.
2. **Запустить выгрузку:**

```bash
python3 scripts/jira_task_digest.py PB-7986 --days 30 --out ARTIFACTS/<слаг>/06-реализация
```

Полезные ключи: `--days N` (окно изменений, по умолчанию 7), `--brief` (без таблицы задач: только сводка по статусам, изменения и застой), `--stuck-days N` (порог «нет движения», 14), `--all-changes` (показать и служебные изменения), `--no-changelog` (быстро, без истории), `--max-children N`, `--json-only`.

3. **Отдать сводку, а не таблицу целиком.** В ответе: сколько задач в семье, распределение по статусам, кто ведёт, что изменилось за окно (с датами), где нет движения, что застряло на ком-то. Когда нужен короткий ответ «что происходит» — запускать с `--brief`: тогда перечисления задач в ответе нет, а полный список смотрится в Jira.
4. **Ответить на вопросы по данным.** Например: «что мешает переходу в прод», «сколько задач ждут груминга», «кто последний трогал задачу». Ответ строится только на выгрузке; чего в данных нет — сказать прямо, а не додумывать.
5. **Снапшот — в папку задачи.** Скрипт кладёт `digest-<KEY>-<дата>.md` и `snapshot-<KEY>-<дата>.json` в `--out`. На следующем запуске он сам покажет «новых задач с прошлой выгрузки» — сравнение идёт с последним снапшотом в этой папке.
6. **Регулярный режим (по запросу).** Ежедневная выгрузка — cron-задание с `--no-changelog --days 1` утром, полная выгрузка с историей — раз в неделю.

## Что попадает в выгрузку

| Источник | Как находится |
|---|---|
| Корень | сама задача (тип, статус, ответственный, даты, описание-ссылка) |
| Эпик → дочерние | JQL `"Epic Link" = <KEY>`, у каждой — подзадачи |
| Стори → подзадачи | поле `subtasks` |
| Родитель | поле `parent` (для подзадач) |
| Связанные задачи | `issuelinks` в обе стороны: Block, Part, Relation, Functional Specification и др. |
| Задачи техкоманды | почти всегда в других проектах (`WEB`, `TRN`, `RMS`, `DS`), связаны со стори через `issuelinks` — их видно только по связям |
| Упоминания | задача, у которой правки описания/комментарии по окну, и задачи, ссылающиеся на ключ |

В дайджесте есть: «Коротко» (статусы, кто ведёт, изменения, застой), таблица задач семьи, таблица изменений за окно (`Было → Стало`), список «без движения больше N дней», связи корневой задачи.

## Режим спринта: статусы для дейли по команде

Агент берёт активный спринт доски команды — то, что нужно на дейли: только задачи текущего спринта, свёрнутые по статусам и людям.

```bash
python3 scripts/jira_task_digest.py --board "iiko Web Features" --project PB --days 1 --brief
python3 scripts/jira_task_digest.py --board 354 --days 1 --brief     # дизайн-команда (Design Scrum)
python3 scripts/jira_task_digest.py --board 354 --component iikoProjectOffice
```

* доска задаётся id или частью названия; если под название подходит несколько досок, скрипт называет их и просит id;
* `--project`, `--component`, `--assignee` — срез конкретной команды внутри спринта;
* `--days 1` — что изменилось со вчера, `--brief` — сводка без таблицы задач;
* если активного спринта у доски нет, скрипт так и говорит — это не ошибка запуска.

Регулярный сбор (cron) — по будням утром до дейли, окно суток, доставка в топик команды. В задании сразу указывать фильтр команды: общие доски отдают больше 1300 задач в спринте, без фильтра сводка нечитаемая.

## Что делать с тем, что нашли

* **Сводку по статусам можно фиксировать в эпике** — в блоке состояния: что уже работает и в каком релизе вышло, что в работе, что осталось. В эпике статусам место.
* **В описания задач таблица задач и списки вопросов не переносятся.** Список задач и так виден в Jira через Epic Link, а вопросы задаются команде, а не пишутся в описание.
* **Правки описаний — отдельный скилл** `requirement-actualization`: три вида изменения требования (данные, пользовательский путь, техническое решение) и только с подтверждения человека.
* Дальше продакт задаёт вопросы по данным — команде, а не поиску по разделам Jira.

## Проверенные факты по Jira iiko

- Проект `PB`, эпики по шагам процесса; задачи разработки — в `WEB` (backend/frontend), `TRN`, `RMS`, `DS`.
- Epic Link — `customfield_11441` (у `PB Design`-задач тоже заполняется).
- Статусы PB: `Open`, `Describing`, `Grooming`, `Ready for grooming`, `Ready for dev`, `In dev`, `ready for approval`, `ready for pilot`, `Ready for deploy`, `piloting`, `released`, `Closed`, `Resolved`.
- Время — МСК (Jira отдаёт `+0300`); скрипт печатает в МСК.
- Скорость: семья из 77 задач (эпик + 38 стори + подзадачи, окно 30 дней) — около 2 секунд.

## Pitfalls

- **Истории изменений нет отдельным эндпоинтом:** `GET /rest/api/2/issue/<KEY>/changelog` → 404, `POST /rest/api/2/changelog/bulkfetch` → 404 на нашем сервере. Работает только `GET /rest/api/2/issue/<KEY>?expand=changelog` (отдаёт историю целиком, до 179 записей проверено).
- **`issueLinkType is not EMPTY` не поддерживается** («The operator 'is not' is not supported»). Связанные задачи искать через `issue in linkedIssues(<KEY>)` или читать поле `issuelinks` у задачи.
- **`text ~ "PB-1234"` работает** и находит задачи, где ключ просто упомянут в тексте — полезно для поиска источника правки, но даёт шум: проверяй каждую находку.
- **Тяжёлый вывод в консоли:** ответ по одной задаче с `expand=changelog` может быть 50 КБ; не печатай сырой JSON в чат, читай его скриптом и отдавай сводку.
- **Служебные изменения в changelog** (связи `Epic Child`, `Link`, worklog) искажают счётчики: по умолчанию скрипт их скрывает и пишет, сколько скрыто; `--all-changes` показывает всё.
- **`jira_search` (Atlassian MCP) по `sprint = N` врёт** — по спринтам брать задачи через доску. В этом скилле это уже сделано: режим `--board` работает через Agile API (`/rest/agile/1.0/board/<id>/sprint?state=active` → `/rest/agile/1.0/sprint/<id>/issue`), а не через JQL.
- **Доска отдаёт спринт целиком.** У общих досок в активном спринте бывает больше 1300 задач (проверено на «iiko Web Features», спринт 9.9.1) — для дейли обязателен фильтр `--project` / `--component` / `--assignee`, иначе сводка нечитаемая.
- **В спринте поле «обновлено» почти всегда свежее:** перемещение задачи в спринт меняет дату. Застой и «нет движения» считать по истории изменений — запускать без `--no-changelog` и с окном от 7 дней.
- **Скилл ничего не пишет в Jira.** Ни описания, ни комментарии: выгрузка read-only. Запись — только через `requirement-actualization` и только с подтверждения.
- **Ключи задач — всегда ссылкой** `https://jira.iiko.ru/browse/<KEY>`; без ссылки пользователь всё равно пойдёт искать вручную.
