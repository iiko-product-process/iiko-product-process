# Шаг 5 — «Подготовка спецификации»

Папка шага 5 продуктового процесса iiko (зона «деливери»): **из подтверждённых продуктовых требований и прототипа получается спека для разработки** по единому стандарту «Формат PRD».

Скилл шага: **`spec-writing` v2.0** (2026-09-27) — автор **Александра Коновалова** (продукт производства готовой еды), формат артефакта согласован с разработкой. Скилл положен сюда целиком, вместе с материалами, на которые он ссылается.

## Что можно сделать

- **Собрать PRD** — скилл `spec-writing`: интервью по банку из 14 групп (по одному вопросу за раз), 9 этапов с гейтами, сборка PRD по стандарту.
- **Опубликовать по формату** — статья в Confluence + MD-файл с тем же содержанием; после заголовка — макрос Jira и оглавление; прототип/промпт/скриншот — вложением.
- **Проверить перед передачей** — чек-лист `skill/references/handoff-checklist.md` (Business / Functional / System / Data / Technical / Delivery + стоп-правила).
- **Посмотреть эталон** — `examples/`: пример PRD (PB-5671 «Реквизиты юр. лица заказчика»), промпт к прототипу и сам прототип.
- **Передать в разработку** — после гейта «approve»: декомпозиция на задачи Jira.

## Что должно получиться в итоге

**PRD по стандарту «Формат PRD»**, по которому разработка берёт работу без восстановления контекста из чатов:

- полный (14 разделов, 5 обязательных) или сокращённый (5 разделов — для локальных правок);
- публикуется как статья в Confluence + MD-файл;
- размер истории — до одной недели разработки; больше — декомпозиция или законченный частный сценарий (исключение — неделимая архитектурная разработка, ≤10–15 задач в год на компанию);
- правила качества: разделять подтверждённые требования / правила систем / решения на усмотрение разработки / открытые вопросы; не додумывать; критерии приёмки — проверяемые и пригодные для автотестов AQA; без служебных пометок и мета-шапки;
- ничего не создаётся без явного аппрува (Jira, Confluence, Pyrus, файлы) — сначала прямой вопрос «Создать?».

## Как устроен скилл (кратко)

1. **Интервью.** Вопросы по одному (следующий — только после ответа), банк из 14 групп; три группы обязательные: ограничения, вопросы к разработке, схемы. Ответы фиксируются в требования, а не остаются в переписке.
2. **9 этапов с гейтами:** бизнес-постановка (гейт «делаем/откладываем») → as-is → to-be (гейт «подтверждено + реализуемо») → системное взаимодействие → сценарии → вводные и ограничения → сборка PRD (гейт «можно оценивать») → ревью (гейт «approve») → передача в разработку (декомпозиция на задачи Jira).

## Связь с другими шагами

- **Вход:** из шага 3 приходят продуктовые требования (проблема, пользователь, ценность, сценарии, критерии приёмки, границы); из шага 4 — дизайн и прототипы. PRD собирает это в спеку для разработки: технические решения и маппинги, API, данные, НФТ, edge cases, фича-флаги и права.
- **Выход:** в шаг 6 «Сопровождение реализации и приёмка» — задача, по которой разработка берёт работу без восстановления контекста из чатов; критерии приёмки пригодны для автотестов.

## Что нужно, чтобы запускать шаг у нас

- Скилл уже установлен в рабочем контейнере: `/opt/data/skills/productivity/spec-writing/`.
- `CONFLUENCE_TOKEN` в `/opt/data/.env` есть — публикация статьи возможна.
- Скилл ссылается на скиллы-спутники, которых у нас пока нет: `publish-md-to-confluence` (публикация статьи + вложений), `iiko-prototypes`, `html-prototype-verification`, `iiko-product-requirements`, `iiko-mcp-servers`. Их стоит либо получить у Александры, либо собрать аналогичные.
- Скилл адаптирован под продукт готовой еды (ПРК, Fabix) — для задач iikoWeb тексты подводных камней и профили команд нужно дополнять.
