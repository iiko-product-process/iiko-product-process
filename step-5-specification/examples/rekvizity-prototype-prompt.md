# Промпт для создания прототипа: реквизиты юрлица заказчика

Создай интерактивный прототип веб-интерфейса на русском языке. Результат — один автономный HTML-файл с встроенными CSS и JavaScript, работающий локально без сборки и внешних зависимостей. Используй только демонстрационные данные; не выполняй сетевые запросы. Следуй требованиям ниже. Они задают целевое поведение; не добавляй продуктовые возможности от себя.

## Назначение

Менеджер производства заполняет реквизиты внешнего заказчика в карточке, чтобы использовать их в УПД. Покажи создание, редактирование и повторное открытие карточки. Backend/RMS и печать имитируются; явно подпиши имитацию.

## Внешний вид

Светлый деловой интерфейс: белый фон, Segoe UI/Arial 14px, основной текст #1c1c1c, вторичный #6e6e6e, акцент #2f6fed, границы #cfcfcf, ошибки #c0392b. Слева светло-серое меню шириной 250px с маршрутом «Ежедневные операции → Производство → Заказчики», активный пункт выделен бледно-синим. Справа заголовок карточки, кнопки «Назад», «Удалить» и одна общая кнопка «Сохранить». Формы просторные, без декоративных иллюстраций. Не меняй порядок вкладок: «Основная информация», «Реквизиты организации», «Настройки ЛК заказчика».

Над приложением — тёмная панель «Управление прототипом»: режим создания/редактирования, флаг включён/выключен/отсутствует, права есть/нет, ответ RMS успех/ошибка/таймаут, «Повторно открыть», «Сбросить демоданные». Эти элементы служат только демонстрации и не входят в продуктовый интерфейс.

## Форма

Основная информация: название, код (при редактировании), имя и фамилия контактного лица, телефон, email, адрес доставки. При создании обязательны название, имя, телефон, email и внешнее меню из настроек ЛК. Для демонстрации настройки ЛК содержат выбор внешнего меню с одним синтетическим вариантом. Не добавляй другие новые настройки ЛК.

Реквизиты: полное наименование на всю ширину; радиогруппа ЮЛ/ИП; строка ИНН, КПП, ОГРН/ОГРНИП; юридический адрес; чекбокс совпадения адресов; фактический адрес; заголовок «Банковские реквизиты»; банк на всю ширину; строка БИК, расчётный счёт, корреспондентский счёт.

Все поля ручного ввода реквизитов необязательные. ЮЛ выбран по умолчанию, пустой выбор невозможен. Полное наименование и каждый адрес — до 500 символов, банк — до 250. Ограничь ввод этими длинами.

Цифровые поля принимают только 0–9 с сохранением ведущих нулей. ИНН: 10 для ЮЛ, 12 для ИП; КПП: 9, доступен только ЮЛ; ОГРН: 13, ОГРНИП: 15; БИК: 9; оба счёта: 20. Показывай маску оставшихся символов. Пустое поле допустимо, частично заполненное подсвечивается красным с точным текстом «Введено N из X цифр» и блокирует сохранение. Контрольные суммы не проверять. При смене ЮЛ/ИП очищать ИНН, КПП и ОГРН/ОГРНИП, обновлять длины и подписи.

Подсказка юридического адреса по значку i: «Адрес по учредительным документам и выписке из ЕГРН: индекс, регион, населённый пункт, улица, дом, офис/помещение (при наличии).» Используй именно ЕГРН.

Чекбокс «Совпадает с юридическим адресом» копирует юридический адрес в фактический и синхронно обновляет его при вводе. Фактический адрес заблокирован. После выключения он редактируемый и сохраняет скопированное значение. Сохраняй сам чекбокс: после сохранения и повторного открытия он остаётся включённым, оба адреса заполнены, фактический заблокирован.

## Состояние и сохранение

При создании кнопка сохранения доступна после заполнения обязательных исходных полей и внешнего меню; при редактировании — после изменения. Неполные цифровые реквизиты отклоняют сохранение и переводят на нужную вкладку. Успех сохраняет демонстрационную карточку и чекбокс в localStorage; повторное открытие загружает сохранённое состояние. Ошибка/таймаут RMS показывают сообщение и не меняют сохранённые данные. Введённый черновик можно оставить для исправления. Тексты имитации ошибки подпиши как демонстрационные, поскольку точные продуктовые тексты не зафиксированы.

Флаг включён — вкладка и заполнение доступны, демонстрация переноса в УПД разрешена. Флаг отсутствует или выключен — вкладка и функциональность недоступны; сохранённые реквизиты не удаляются. После повторного включения доступны сохранённые данные. Без прав чтение и изменение реквизитов недоступны.

«Назад» отбрасывает несохранённые изменения. «Удалить» доступно только при редактировании: имитируй soft-delete. В демонстрационной панели предоставь восстановление, возвращающее сохранённые реквизиты. Не выполняй реальные удаления.

## Границы демонстрации

Не создавай юридически значимую печатную форму УПД и не выдумывай расположение полей. Допустим информационный блок вне продуктовой формы: «Передача реквизитов в УПД доступна/недоступна». Маппинг реальной формы определяет разработчик. Синхронизацию RMS → веб, подтягивание по ИНН и EDI не добавлять.

Реальные правила систем: пустые значения не сериализуются в RMS и не стирают старые значения RMS; непустые переданные значения обновляются. Атомарное сохранение в двух системах обеспечивается существующей архитектурой. В прототипе достаточно локальной имитации результата, без воспроизведения серверной архитектуры.

## Самопроверка результата

Проверь переключение ЮЛ/ИП, неполный ИНН, частично заполненную карточку, сохранение и повторное открытие с включённым совпадением адресов, выключение флага без удаления данных, отсутствие прав, успешное сохранение и ошибку RMS. Не добавляй непроверенные заявления о работе реальных API.
