# Установка прототипа гипотез (шаг 2) на сервер сотрудника

Инструкция для развёртывания на «своём» сервере (рабочая машина, домашний сервер, контейнер): прототип работает как веб-сервис, списки гипотез лежат файлами в репозитории, все свои гипотезы сотрудник собирает в одном месте — в общем списке-реестре.

## Что можно сделать

- **Поставить прототип на свой сервер** — `install/install.sh` одной командой (быстрая установка ниже).
- **Поставить вручную** — `server/serve.py` + автоподъём через cron или systemd (инструкция ниже).
- **Открыть доступ снаружи** — порт, firewall, авторизация.
- **Проверить, что всё работает** — чек-лист из 6 пунктов.
- **Обновить и перезапустить** — `git pull` + `hypoproto_restart.sh`.
- **Разобраться с проблемой** — таблица «Диагностика».

## Что должно получиться в итоге

- Ссылка вида `http://<адрес-сервера>:8330/?list=obshiy-spisok` — открывается калькулятор гипотез в веб-режиме.
- Любая правка (новая гипотеза, оценка, отметка «в работу», ключ Jira) **сохраняется автоматически** в `data/lists/*.json` и уезжает в git-коммит (если репозиторий подключён к remote).
- **Все гипотезы в одном месте:** общий список — реестр (свои гипотезы + копии из списков по проблемам), переключение между списками — в боковом меню по кнопке-бургеру; сводный файл `data/hypotheses.json` собирается автоматически.
- Сервис **сам поднимается** после перезагрузки и восстановливается, если упал (watchdog в cron).
- На том же сервере может работать канал «Спросить Hermes» (кнопка в шапке прототипа) — если там установлен Hermes.

## Требования

| Что | Зачем | Обязательно |
|---|---|---|
| Python 3.8+ | сервис и скрипты (`server/serve.py`, `scripts/*.py`) — **только стандартная библиотека**, ничего ставить не нужно | да |
| curl | проверки здоровья в скриптах | да |
| git | локальная история правок | желательно (без git всё работает, история не ведётся) |
| 1 свободный TCP-порт | по умолчанию 8330 (из диапазона прототипов `PROTO_PORT_RANGE=8330-8339`) | да |
| Hermes на той же машине | только для кнопки «Спросить Hermes» | нет |

## Быстрая установка

```bash
# 1. получить папку шага (взять из папки процесса или распаковать архив шага)
cp -r <папка процесса>/02-hypotheses ~/02-hypotheses && cd ~/02-hypotheses

# 2. установить
bash install/install.sh --port 8330                  # без пароля (для личного сервера)
bash install/install.sh --port 8330 --auth iiko:пароль   # с паролем (для общего сервера)
```

Скрипт `install.sh` делает шесть шагов:

1. проверяет зависимости (python3 ≥ 3.8, curl, при наличии — git);
2. создаёт каталоги данных и, если нужно, пустой общий список (`data/lists/obshiy-spisok.json`) с набором целей;
3. при `--auth` создаёт файл авторизации `.hypoproto-auth.txt` (внутри папки шага) (в git не попадает, права 600);
4. записывает настройки установки в `.hypoproto/env` (`PORT`, `HOST`) — их читают watchdog и restart, чтобы работать именно с этой установкой;
5. ставит в cron автоподъём сервиса: каждые 15 минут и при загрузке (`@reboot`); отключается флагом `--no-cron`;
6. запускает сервис и проверяет, что он отвечает;
7. печатает ссылку для сотрудника и что осталось сделать (открыть порт, передать пароль).

Флаги: `--port 8330`, `--host 0.0.0.0`, `--auth логин:пароль`, `--no-cron`.
Переменные: `HYPOPROTO_PORT`, `HYPOPROTO_HOST`, `HYPOPROTO_LOG`, `HYPOPROTO_AUTH_FILE`.

После установки порт и адрес хранятся в `02-hypotheses/.hypoproto/env` — этот файл читают `hypoproto_ensure.sh` и `hypoproto_restart.sh`, поэтому их можно запускать без аргументов. Переменные окружения важнее файла.

## Ручная установка (без install.sh)

```bash
cd 02-hypotheses
python3 server/serve.py --port 8330 --host 0.0.0.0            # запуск
python3 server/serve.py --port 8330 --auth iiko:пароль         # со своим паролем
```

Автоподъём — одна из двух схем:

```bash
# А) cron (как делает install.sh)
crontab -e
*/15 * * * * HYPOPROTO_PORT=8330 bash /путь/02-hypotheses/install/hypoproto_ensure.sh
@reboot      HYPOPROTO_PORT=8330 bash /путь/02-hypotheses/install/hypoproto_ensure.sh
```

```ini
# Б) systemd (пример: /etc/systemd/system/hypoproto.service)
[Unit]
Description=Прототип гипотез (шаг 2)
After=network.target

[Service]
WorkingDirectory=/путь/02-hypotheses
ExecStart=/usr/bin/python3 server/serve.py --port 8330 --host 0.0.0.0
Restart=always
RestartSec=5
Environment=HOME=/home/<пользователь>

[Install]
WantedBy=multi-user.target
```

## Доступ снаружи сервера

- Сервис слушает `0.0.0.0` (все интерфейсы). Если нужен только локальный доступ — `--host 127.0.0.1`.
- Открой порт в firewall: например `sudo ufw allow 8330/tcp`. В Docker — проброс порта (`-p 8330:8330`).
- Если сервис общий — включай `--auth` (HTTP Basic). Без пароля любой, кто видит порт, может править списки (а при настроенном Hermes — ещё и запускать агента кнопкой «Спросить Hermes»).
- Пароль и логин передавай сотрудникам отдельно от ссылки; файл `.hypoproto-auth.txt` (внутри папки шага) в git не коммитится.

## Где лежат данные и как устроено «всё в одном месте»

| Файл | Что это |
|---|---|
| `data/lists/obshiy-spisok.json` | **Общий список — реестр всех гипотез**: свои (внесённые вручную) + копии из списков по проблемам |
| `data/lists/problema-<слаг>.json` | Список гипотез по одной конкретной проблеме (в метаданных — формулировка проблемы) |
| `data/problems/<слаг>.md` | Проблемная карта: постановка, требования, цитаты встреч, открытые вопросы |
| `data/hypotheses.json` | Сводный файл всех гипотез (генерируется, каждая гипотеза — один раз) |

- Копии в реестре помечаются `srcList`/`srcListTitle` — в интерфейсе у них бейдж «из «…»».
- Синхронизацию делает `scripts/sync_general.py`, он запускается автоматически из `scripts/aggregate.py` при каждом сохранении.
- Правки не затираются: у гипотез есть поле `upd` (время правки в интерфейсе).
- **Перенос на другой сервер = скопировать папку процесса**: все списки, карты и история едут внутри. Отдельно переносятся только `.hypoproto-auth.txt` (пароль) и настройки автозапуска.

## Проверка после установки (чек-лист)

- [ ] `curl http://127.0.0.1:8330/healthz` → `{"status": "ok", ...}`.
- [ ] Открывается страница списка: заголовок «Гипотезы и оценка ICE × цели компании», вкладки и таблица.
- [ ] Создай тестовую гипотезу в форме → она появилась в таблице; в `data/lists/obshiy-spisok.json` появилась запись; в `git log` — свежий коммит (если git подключён).
- [ ] Бургер в шапке открывает боковое меню: видны все списки с количеством гипотез, текущий подсвечен.
- [ ] Перезапуск: `kill` процесса сервиса → в течение ≤15 минут он поднялся сам (cron) или сразу (systemd `Restart=always`).
- [ ] Если Hermes на машине — кнопка «Спросить Hermes» принимает запрос и возвращает ответ; все запросы идут в один чат.

## Обновление и перезапуск

```bash
git pull                                              # обновить код и данные
bash install/hypoproto_restart.sh                      # перезапустить сервис
```

Перезапуск обязателен после правок `server/serve.py` — код читается один раз при старте.

## Диагностика

| Симптом | Что делать |
|---|---|
| Браузер просит логин/пароль | Включена авторизация. Логин/пароль — у того, кто ставил сервис |
| `401` в API | То же: запрос без авторизации |
| «Hermes уже занят другим запросом» (409) | Идёт другой запрос к Hermes — подождать 1–3 минуты |
| `500` при сохранении | Смотреть `.hypoproto/serve.log`; данные при этом уже сохранены локально |
| Страница открывается, но список пустой | Проверь идентификатор: `curl http://127.0.0.1:8330/api/lists` — какие списки есть |
| Сервис не поднимается | `cat .hypoproto/serve.log`; проверить, что порт свободен: `ss -ltnp \| grep 8330` |
| Watchdog молчит | Так и должно быть: пустой вывод = всё в порядке. Проверь, что задание есть: `crontab -l \| grep hypoproto` |

## Файлы установки

| Файл | Что делает |
|---|---|
| `install.sh` | установка в один шаг (зависимости, данные, авторизация, cron, запуск, проверка) |
| `hypoproto_ensure.sh` | автоподъём сервиса + страховочный коммит правок, сделанных не через сервис. Тихий, когда всё в порядке |
| `hypoproto_restart.sh` | аккуратный перезапуск (остановить текущий процесс по порту и поднять заново) |
