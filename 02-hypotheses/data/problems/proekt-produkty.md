# Проблема: «Продукты» — закупки для ресторанов (проблемная карта)

**Статус:** собрано 01.10.2026 · шаг 2 · источники: исследования задачи `Задачи/proekt-produkty/` (карточка проблемы, анализ рынка, бенчмарки, джобы)

## 1. Постановка
Проект «Продукты» — новая закупочная платформа iiko для ресторанов (презентация, 38 слайдов; цель — +15 млрд выручки за 5 лет, сл. 4). Три концепции: маркетплейс / агрегатор-поставщик / агрегатор через ЛК. Целевые контрагенты — средние и мелкие заведения; двусторонняя платформа (ресторан + поставщик).

## 2. Как сейчас (из исследований)
- Заказы идут через мессенджеры и десятки кабинетов — потери, ошибки, рутина (сл. 6.4, 9; MixCart-кейс: закупка 3 ч → 10–15 мин/день).
- Цены меняются еженедельно; матрица ~400 позиций; вручную мониторить невозможно, переплаты не видны (сл. 6.2, 8).
- Сравнение КП идёт по витринной цене; отсрочка и полная экономика не учитываются (сл. 6.6; vc.ru 21.09.2026: «отсрочка = кредит со ставкой»).
- Поиск поставщиков — через знакомых, без базы и репутаций (сл. 6.1).
- Поставщики: дорогой полевой вывод продукта, нет данных о спросе (сл. 7.2, 7.3).

## 4. Открытые вопросы
- Выбор концепции / модель монетизации (ресторан бесплатно — платит поставщик: стандарт рынка).
- Сегментный приоритет: малые (владелец/шеф) vs средние (закупщик) vs сети.
- Готовность поставщиков платить за данные о спросе (свободное поле, подтверждения нет).
