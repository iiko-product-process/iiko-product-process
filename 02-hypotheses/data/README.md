## Файл списка (`data/lists/*.json`)

Один файл = один список гипотез. Общий список — `obshiy-spisok.json`, список по проблеме — `problema-<слаг>.json`.

```json
{
  "list": {
    "id": "problema-onboarding",
    "title": "Онбординг: конверсия в первый заказ",
    "type": "problem",
    "problem": "на регистрации отваливается 60% новых клиентов",
    "owner": "Павел Малофеев",
    "created": "2026-09-29",
    "updated": "2026-09-29"
  },
  "goals": [
    {"id": "g32", "name": "Годовая: цифровизация процессов, +20% критичных", "g": 1.7, "kind": "year"},
    {"id": "q", "name": "Квартальная: OKR продукта", "g": 1.4, "kind": "quarter"}
  ],
  "items": [
    {
      "id": "p1",
      "name": "Если сократить онбординг до трёх шагов, тогда доля дошедших до первого заказа вырастет, так как меньше отваливаются на регистрации",
      "metric": "18% → 25%",
      "src": "воронка в аналитике",
      "I": 7, "C": 6, "E": 6,
      "goals": [["g32", 1]],
      "sel": false,
      "jira": "PB-1234"
    }
  ]
}
```

Поля:

| Поле | Смысл |
|---|---|
| `list.type` | `general` — общий список, `problem` — список по проблеме. |
| `list.problem` | Формулировка проблемы (для списков по проблеме). |
| `goals[]` | Цели с весами: `g` — коэффициент (0.8–2.0, у обязательных 0), `kind` — уровень. Список целей одинаков для всех списков квартала. |
| `items[].name` | Формулировка гипотезы строго «Если …, тогда …, так как …». |
| `items[].metric` | Метрика `baseline → target`; если baseline неизвестен — «уточнить». |
| `items[].src` | Источник данных для метрики (или пусто). |
| `items[].I` / `C` / `E` | Оценки 1–10. |
| `items[].goals` | До двух пар `[цель, α]`, Σα = 1. Пустой массив — базовый коэффициент 1.0. |
| `items[].sel` | Отмечено «в работу» в прототипе. |
| `items[].jira` | Ключ задачи в Jira, когда она создана. |

Итоговый балл считается в прототипе: `I × C × E × G`, где `G = Σ αⱼ × gⱼ`.

## Сводный файл (`data/hypotheses.json`)

Генерируется скриптом `../scripts/aggregate.py` из всех файлов `lists/*.json`:

- `lists[]` — оглавление: id, название, тип, проблема, файл, число гипотез;
- `items[]` — все гипотезы подряд, у каждой добавлено поле `list` с id списка;
- `count`, `updated`.

Править руками не нужно: источник истины — файлы списков.

## Общий список — реестр всех гипотез

По решению Павла (29.09.2026) гипотезы из списков по проблемам **сразу дублируются в общий список**: он читается как реестр всего, что есть.

- свои гипотезы общего списка (без поля `srcList`) живут только там;
- копии из списков по проблемам помечены `srcList` (id списка) и `srcListTitle` (название) — в интерфейсе у них бейдж «из «…»»;
- синхронизацию делает `scripts/sync_general.py`, он запускается автоматически из `aggregate.py` (а значит и при каждом сохранении через сервис);
- правки не затираются: у гипотез есть поле `upd` (время правки в интерфейсе) — если копию правили позже источника, синхронизация оставляет правку копии;
- в сводном `hypotheses.json` каждая гипотеза считается один раз (копии из общего списка пропускаются).
